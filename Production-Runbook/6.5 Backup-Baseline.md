# 6.5 Backup baseline (before customers)

> Last step of this build. Goal: AD, the VMM database and the VMM server can be recovered **before** any customer lands on the platform.
> If Etisalat has a backup product (Veeam, Commvault, DPM, …), use it for the same scope and schedules, and keep this file as the minimum standard.
> **Backups must not live only on the CSV.** Every backup below is copied to a target outside HVCL01 (`<BACKUP-SHARE>`, provided by Etisalat, 0.2 §1).

| What | How | Schedule (placeholder) | Retention (placeholder) | Local target | Off-cluster copy |
|---|---|---|---|---|---|
| DC01, DC02 | System state (Windows Server Backup) | Daily 23:00 | 14 versions | `B:` (backup VHDX) | `<BACKUP-SHARE>\AD\<DC>` |
| `VirtualManagerDB`, `master`, `msdb` | SQL Agent job, full backups, compressed + checksum (runs after the VMM backup, so it copies that night's VMM DB backup too) | Daily 03:00 | 14 days | SQL01 `B:\SQLBackup` | `<BACKUP-SHARE>\SQL01` |
| VMM | `Backup-SCVMMServer` + registry export + VMM01 system state | Daily 02:00 | 14 days | SQL01 `B:\VMMBackup` / VMM01 `B:` | `<BACKUP-SHARE>\VMM` |
| VMM library | Copy of `L:\MSSCVMMLibrary` | Weekly | 4 copies | – | `<BACKUP-SHARE>\VMMLibrary` |

> DKM keys live in AD, so they're covered by the DC system state backups.

## 1. Backup disks (one per VM)

A dedicated backup VHDX per VM, so a backup never fills the OS or data volume:

```powershell
# HV01 (DC01 – local disk on HV01; use HV02 for DC02 with the same block)
New-VHD -Path "D:\VMs\DC01\Virtual Hard Disks\DC01-Backup.vhdx" -SizeBytes 100GB -Dynamic | Out-Null
Add-VMHardDiskDrive -VMName DC01 -Path "D:\VMs\DC01\Virtual Hard Disks\DC01-Backup.vhdx"
```

```powershell
# HV0x (the node that owns SQL01 / VMM01) – both VMs are on the CSV
$csv = "C:\ClusterStorage\CSV01"
New-VHD -Path "$csv\SQL01\Virtual Hard Disks\SQL01-Backup.vhdx" -SizeBytes 200GB -Dynamic | Out-Null
Add-VMHardDiskDrive -VMName SQL01 -Path "$csv\SQL01\Virtual Hard Disks\SQL01-Backup.vhdx"
New-VHD -Path "$csv\VMM01\Virtual Hard Disks\VMM01-Backup.vhdx" -SizeBytes 100GB -Dynamic | Out-Null
Add-VMHardDiskDrive -VMName VMM01 -Path "$csv\VMM01\Virtual Hard Disks\VMM01-Backup.vhdx"
```

Inside each VM (DC01, DC02, SQL01, VMM01):

```powershell
# DC01 / DC02 / SQL01 / VMM01 (each)
Get-Disk | Where-Object PartitionStyle -eq 'RAW' | Initialize-Disk -PartitionStyle GPT -PassThru |
    New-Partition -DriveLetter B -UseMaximumSize | Format-Volume -FileSystem NTFS -NewFileSystemLabel "Backup" -Confirm:$false
```

## 2. DC01 / DC02: system state

```powershell
# DC01 (then DC02 with its own name in the copy path)
Install-WindowsFeature Windows-Server-Backup

# Test run now
wbadmin start systemstatebackup -backupTarget:B: -quiet

# Daily scheduled task: backup, keep the last 14, copy off-cluster
New-Item -ItemType Directory -Path C:\Scripts -Force | Out-Null
@'
wbadmin start systemstatebackup -backupTarget:B: -quiet
wbadmin delete systemstatebackup -keepVersions:14 -quiet
robocopy B:\WindowsImageBackup "<BACKUP-SHARE>\AD\$env:COMPUTERNAME" /MIR /R:2 /W:30 /NP /LOG:C:\Windows\Temp\ad-backup-copy.log
'@ | Set-Content C:\Scripts\Backup-SystemState.ps1
$a = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-NoProfile -ExecutionPolicy Bypass -File C:\Scripts\Backup-SystemState.ps1"
$t = New-ScheduledTaskTrigger -Daily -At 23:00
Register-ScheduledTask -TaskName "BKP - System State" -Action $a -Trigger $t -User "SYSTEM" -RunLevel Highest -Force
Start-ScheduledTask -TaskName "BKP - System State"     # test the full task (backup + copy) once
```

The copy runs as SYSTEM, so the DC computer account (`DC01$`) needs write access on `<BACKUP-SHARE>\AD`.

## 3. SQL01: SQL Agent job (VirtualManagerDB + master + msdb)

```powershell
# SQL01
New-Item -ItemType Directory -Path B:\SQLBackup, B:\VMMBackup -Force | Out-Null
icacls B:\SQLBackup /grant "NT Service\MSSQLSERVER:(OI)(CI)M" "NT Service\SQLSERVERAGENT:(OI)(CI)M"
icacls B:\VMMBackup /grant "NT Service\MSSQLSERVER:(OI)(CI)M" "NT Service\SQLSERVERAGENT:(OI)(CI)M"
```

Run in SSMS on MGMT01 (connected to `SQL01`):

```sql
-- SQL01 (SSMS from MGMT01)
USE msdb;
DECLARE @job sysname = N'BKP - VMM DB + system DBs (daily)';
EXEC dbo.sp_add_job @job_name = @job;

EXEC dbo.sp_add_jobstep @job_name = @job, @step_name = N'1 Full backups', @subsystem = N'TSQL',
     @database_name = N'master', @on_success_action = 3,
     @command = N'
DECLARE @d nvarchar(20) = FORMAT(GETDATE(), ''yyyyMMdd_HHmm''), @f nvarchar(400), @db sysname;
DECLARE c CURSOR LOCAL FAST_FORWARD FOR
    SELECT name FROM sys.databases WHERE name IN (N''VirtualManagerDB'', N''master'', N''msdb'');
OPEN c; FETCH NEXT FROM c INTO @db;
WHILE @@FETCH_STATUS = 0
BEGIN
    SET @f = N''B:\SQLBackup\'' + @db + N''_'' + @d + N''.bak'';
    BACKUP DATABASE @db TO DISK = @f WITH COMPRESSION, CHECKSUM, INIT;
    FETCH NEXT FROM c INTO @db;
END
CLOSE c; DEALLOCATE c;';

EXEC dbo.sp_add_jobstep @job_name = @job, @step_name = N'2 Cleanup older than 14 days', @subsystem = N'PowerShell',
     @on_success_action = 3,
     @command = N'Get-ChildItem B:\SQLBackup, B:\VMMBackup -File | Where-Object LastWriteTime -lt (Get-Date).AddDays(-14) | Remove-Item -Force';

EXEC dbo.sp_add_jobstep @job_name = @job, @step_name = N'3 Copy off-cluster', @subsystem = N'PowerShell',
     @command = N'
robocopy B:\SQLBackup "<BACKUP-SHARE>\SQL01" *.bak /MIR /R:2 /W:30 /NP
if ($LASTEXITCODE -ge 8) { throw "robocopy SQLBackup failed: $LASTEXITCODE" }
robocopy B:\VMMBackup "<BACKUP-SHARE>\VMM\DB" /MIR /R:2 /W:30 /NP
if ($LASTEXITCODE -ge 8) { throw "robocopy VMMBackup failed: $LASTEXITCODE" }',
     @on_success_action = 1;

EXEC dbo.sp_add_schedule @schedule_name = N'Daily 03:00', @freq_type = 4, @freq_interval = 1, @active_start_time = 030000;
EXEC dbo.sp_attach_schedule @job_name = @job, @schedule_name = N'Daily 03:00';
EXEC dbo.sp_add_jobserver @job_name = @job, @server_name = N'(local)';

-- Test run now
EXEC dbo.sp_start_job @job_name = @job;
```

- Step 3 also copies the VMM DB backups from §4 (`B:\VMMBackup`). robocopy exit codes 0–7 mean success. The step fails only on ≥ 8.
- The Agent service reaches the share as `SQL01$`. Grant `SQL01$` write access on `<BACKUP-SHARE>\SQL01` and `<BACKUP-SHARE>\VMM\DB`.

## 4. VMM: Backup-SCVMMServer + registry + system state

Microsoft: the backup folder must **not** be a root directory and must be **reachable by SQL Server**. The path is used by SQL Server on SQL01, so `B:\VMMBackup` (created in §3) is the SQL01 disk.

```powershell
# VMM01 (VMM PowerShell) – test run now
Import-Module VirtualMachineManager
Get-SCVMMServer -ComputerName VMM01.etisalat.local | Backup-SCVMMServer -Path "B:\VMMBackup"
```

Daily, plus the items Microsoft lists next to the DB backup (registry `Settings` key, system state of the VMM server for its SID):

```powershell
# VMM01
Install-WindowsFeature Windows-Server-Backup
New-Item -ItemType Directory -Path C:\Scripts -Force | Out-Null
@'
Import-Module VirtualMachineManager
Get-SCVMMServer -ComputerName VMM01.etisalat.local | Backup-SCVMMServer -Path "B:\VMMBackup"     # B: of SQL01 (path used by SQL Server)
reg export "HKLM\SOFTWARE\Microsoft\Microsoft System Center Virtual Machine Manager Server\Settings" B:\VMM-Settings.reg /y
wbadmin start systemstatebackup -backupTarget:B: -quiet
wbadmin delete systemstatebackup -keepVersions:14 -quiet
robocopy B:\ "<BACKUP-SHARE>\VMM\VMM01" VMM-Settings.reg /R:2 /W:30 /NP
robocopy B:\WindowsImageBackup "<BACKUP-SHARE>\VMM\VMM01\WindowsImageBackup" /MIR /R:2 /W:30 /NP
if ((Get-Date).DayOfWeek -eq 'Sunday') { robocopy L:\MSSCVMMLibrary "<BACKUP-SHARE>\VMMLibrary" /MIR /R:2 /W:30 /NP }
'@ | Set-Content C:\Scripts\Backup-VMM.ps1
$a = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-NoProfile -ExecutionPolicy Bypass -File C:\Scripts\Backup-VMM.ps1"
$t = New-ScheduledTaskTrigger -Daily -At 02:00
Register-ScheduledTask -TaskName "BKP - VMM" -Action $a -Trigger $t -User "ETISALAT\svc-vmm" -Password (Read-Host "svc-vmm password") -RunLevel Highest -Force
Start-ScheduledTask -TaskName "BKP - VMM"      # test run now
```

- The task runs as `svc-vmm`, a VMM Administrator. Give it write access on `<BACKUP-SHARE>\VMM` and `\VMMLibrary`.
- The VMM DB `.bak` files land on SQL01 `B:\VMMBackup` and are copied off-cluster by step 3 of the SQL01 job (§3). The SQL job (03:00) runs after the VMM backup (02:00), so the copy is the same night.
- The library copy runs on Sundays (weekly, per the table).
- When restoring: restore the DB first (SQL tools or `SCVMMRecover.exe`), and don't import the `Sql` subkey from the registry export if the DB location changed (Microsoft "Back up and restore VMM").

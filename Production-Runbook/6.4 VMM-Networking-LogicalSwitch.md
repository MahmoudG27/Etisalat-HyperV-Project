# 6.4 VMM networking: logical networks → uplink port profile → logical switch → convert the host SET switch

> Run in the **VMM console on MGMT01**.
> Goal: VMM takes ownership of the `LS-Converged` SET switch built in 1.1, **without recreating it** and without interrupting DC/SQL/VMM traffic.
> This is the state Microsoft requires before deploying the Network Controller ("management logical network" + "management logical switch deployed on the hosts").

```
Logical Network "Management"  ── site Management_0    (VLAN 100, 10.10.100.0/24) ── IP pool IPP-Management
Logical Network "LiveMigration" ── site LiveMigration_0 (VLAN 101, 10.10.101.0/24)
                     │
                     ▼
Uplink Port Profile "UPP-Converged"   (SET, Hyper-V Port, sites: Management_0 + LiveMigration_0  [+ HNV-PA_0 in 6.6])
                     │
                     ▼
Logical Switch "LS-Converged"         (Embedded Team, Weight, no extensions)
                     │  Convert to Logical Switch (no downtime)
                     ▼
HV01..HV04 : SET switch "LS-Converged" (NIC1+NIC2) + vNICs Management / LiveMigration
```

## 1. Logical network: Management

**Fabric → Networking → Logical Networks → Create Logical Network**

| Page | Value |
|---|---|
| Name | `Management` |
| Settings | **Connected network** (one connected network) ✔ · ✔ **Create a VM network with the same name to allow virtual machines to access this logical network directly** · ✘ Managed by Microsoft Network Controller (NC doesn't exist yet) |
| Network Site → Add | Name `Management_0` · Host group ✔ **SDN** · VLAN **100** · IP subnet **10.10.100.0/24** |

Then right-click **Management → Create IP Pool**:

| Field | Value |
|---|---|
| Name | `IPP-Management` |
| Network site / subnet | `Management_0` / 10.10.100.0/24 |
| Range | **10.10.100.51 – 10.10.100.99** |
| **IP addresses to be reserved for other uses** | **10.10.100.50** (NC REST IP, required because the 3 NC nodes are in the same subnet) |
| Gateway | 10.10.100.1 |
| DNS servers / suffix | 10.10.100.21, 10.10.100.22 / `etisalat.local` |

> Microsoft: don't use the first 3 addresses of the subnet in the pool. .1–.49 hold the static infrastructure IPs, so the pool starts at .51.

## 2. Logical network: LiveMigration

| Page | Value |
|---|---|
| Name | `LiveMigration` |
| Settings | Connected network ✔ · ✔ create VM network with same name |
| Network Site | `LiveMigration_0` · Host group **SDN** · VLAN **101** · 10.10.101.0/24 |

No IP pool is needed: the host vNICs keep their static IPs from 1.1.

## 3. Port classifications (use the built-in ones)

Fabric → Networking → **Port Classifications**: confirm these exist (they're built in):
- `Host management`
- `Live migration workload`
- `Medium bandwidth` (default for VMs)

## 4. Uplink port profile

**Fabric → Networking → Port Profiles → Create Hyper-V Port Profile**

| Field | Value |
|---|---|
| Name | `UPP-Converged` |
| Type | **Uplink port profile** |
| Load balancing algorithm | **Hyper-V Port** |
| Teaming mode | **Switch Independent** |
| Network configuration | ✔ `Management_0` · ✔ `LiveMigration_0` |
| "Enable Hyper-V Network Virtualization" | ✘ **leave unchecked** (that's the old HNVv1. SDN with NC doesn't use it) |

## 5. Logical switch

**Fabric → Networking → Logical Switches → Create Logical Switch**

| Page | Value |
|---|---|
| General | Name **`LS-Converged`** (exactly the same name as the host switch) · Uplink mode **Embedded Team** |
| Settings | Minimum bandwidth mode **Weight** · SR-IOV ✘ · "Managed by Microsoft Network Controller": ✘ **not now**. NC onboarding (6.5) converts the switch to an SDN switch automatically |
| Extensions | **Clear ALL extensions.** Microsoft: any extension selected here can block NC onboarding later |
| Virtual Port | Add `Host management`, `Live migration workload`, `Medium bandwidth` (set **Medium bandwidth** as default) |
| Uplink | Add `UPP-Converged` |
| Uplink → **New Network Adapter** #1 | Name `Management` · VM network `Management` · VLAN 100 · ✔ **This network adapter will be used for host management** · ✔ **Inherit connection settings from the host adapter** · Port classification `Host management` |
| Uplink → **New Network Adapter** #2 | Name `LiveMigration` · VM network `LiveMigration` · VLAN 101 · IP: none/static · Port classification `Live migration workload` |

## 6. Convert the host switch to the logical switch (one host at a time)

### 6.1 Pre-check (the settings must match)

```powershell
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock {
    $s = Get-VMSwitch -Name "LS-Converged"
    [pscustomobject]@{
        Host = $env:COMPUTERNAME; Switch = $s.Name; SET = $s.EmbeddedTeamingEnabled
        BandwidthMode = $s.BandwidthReservationMode; IOV = $s.IovEnabled
        LB = (Get-VMSwitchTeam -Name $s.Name).LoadBalancingAlgorithm
    }
} | Format-Table Host, Switch, SET, BandwidthMode, IOV, LB
```

Expected on all: `SET=True, BandwidthMode=Weight, IOV=False, LB=HyperVPort`. This must match the logical switch: Embedded Team / Weight / no SR-IOV / Hyper-V Port.

### 6.2 Convert

Start with **HV04** (no DC on it), then HV03, HV02, HV01.

**Fabric → Servers → All Hosts → SDN → HVCL01 → HV04 → Properties → Virtual Switches**
→ select `LS-Converged` (shown as a *Standard switch*) → **Convert to Logical Switch**
→ Logical switch `LS-Converged` · Uplink port profile `UPP-Converged` → **Convert**.

Microsoft documents this as non-disruptive. If any step fails, nothing is changed.
Keep a continuous ping running from MGMT01 to HV04 during the job: `ping -t 10.10.100.14`.

### 6.3 Map the existing host vNICs

Same window (host **Properties → Virtual Switches**), under `LS-Converged`:

| Host vNIC | VM network | VLAN | Port classification |
|---|---|---|---|
| Management | `Management` | 100 | Host management |
| LiveMigration | `LiveMigration` | 101 | Live migration workload |

OK → refresh the host. Repeat 6.2 and 6.3 for HV03, HV02, HV01.

### 6.4 Compliance

**Fabric → Networking → Logical Switches** → ribbon **Hosts** view → each host/adapter must show **Fully compliant**.
If one is "Not compliant", right-click → **Remediate**.

### 6.5 Fallback (only if "Convert to Logical Switch" fails or isn't offered)

Microsoft's documented script for SET switches. Run it **on the host**. It only tags the existing switch, so there's no network change.
(Fixed bug from the docs: the original uses an undefined `$PortProfileName`.)

```powershell
# On MGMT01 (VMM PowerShell): get the IDs
(Get-SCLogicalSwitch -Name "LS-Converged").ID
Get-SCUplinkPortProfileSet | Where-Object { $_.LogicalSwitch.Name -eq "LS-Converged" } | Format-Table Name, ID
```

```powershell
# On the host
$VirtualSwitchName  = "LS-Converged"
$LogicalSwitchId    = "<ID of LS-Converged>"
$PortProfileSetName = "<Name of the uplink port profile set, e.g. UPP-Converged_xxxx>"
$PortProfileSetId   = "<ID of that uplink port profile set>"

$vswitch = Get-VMSwitch -Name $VirtualSwitchName
$VMMFeatureId     = "8b54c928-eb03-4aff-8039-99171dd900ff"
$VMMPortFeatureId = "1f59a509-a6ba-4aba-8504-b29d542d44bb"

$defaultFeature = Get-VMSystemSwitchExtensionSwitchFeature -FeatureId $VMMFeatureId
$defaultFeature.SettingData.LogicalSwitchId   = $LogicalSwitchId
$defaultFeature.SettingData.LogicalSwitchName = $VirtualSwitchName
Add-VMSwitchExtensionSwitchFeature -SwitchName $VirtualSwitchName -VMSwitchExtensionFeature $defaultFeature

$defaultPortFeature = Get-VMSystemSwitchExtensionPortFeature -FeatureId $VMMPortFeatureId
$defaultPortFeature.SettingData.PortProfileSetId   = $PortProfileSetId
$defaultPortFeature.SettingData.PortProfileSetName = $PortProfileSetName
$defaultPortFeature.SettingData.NetCfgInstanceId   = "{" + $vswitch.Id + "}"
Add-VMSwitchExtensionPortFeature -SwitchName $VirtualSwitchName -VMSwitchExtensionFeature $defaultPortFeature -ExternalPort
```

Then in VMM: right-click the host → **Refresh**, and check that the switch now shows as a logical switch.

## 7. Attach the infrastructure VMs to the VM network

DC01/DC02/SQL01/VMM01/MGMT01 were created outside VMM (VLAN set with Hyper-V cmdlets). Assign them to the VMM **VM network** now, **before** NC onboarding, so VMM manages their switch ports.

Start with **MGMT01** and confirm it still pings. Then do the others:

```powershell
$vmn = Get-SCVMNetwork -Name "Management"
$pc  = Get-SCPortClassification -Name "Medium bandwidth"
foreach ($n in "MGMT01","DC01","DC02","SQL01","VMM01") {
    $vm = Get-SCVirtualMachine -Name $n
    Get-SCVirtualNetworkAdapter -VM $vm |
        Set-SCVirtualNetworkAdapter -VMNetwork $vmn -VLanEnabled $true -VLanID 100 -PortClassification $pc
    Write-Host "$n done"; Start-Sleep 10
}
```

(Console alternative: VM → Properties → Hardware Configuration → Network Adapter 1 → **Connected to a VM network** `Management`, VLAN 100, classification `Medium bandwidth`.)

- All 4 hosts: `LS-Converged` = logical switch, **Fully compliant**.

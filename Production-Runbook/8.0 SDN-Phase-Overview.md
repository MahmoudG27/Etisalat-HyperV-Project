# 8.0 SDN fabric phase – overview

> **Starts** where the build ends: Gate 6.6 passed (VMM manages HVCL01 with `LS-Converged`, backups and CAU in place).
> **Ends** with a working, validated SDN fabric (Network Controller + SLB/MUX + RAS Gateway) **before any customer** is onboarded.
> Customer onboarding and the VMware migration are a **later phase** and aren't covered here.
> Every value marked `<…>` comes from Etisalat (0.2). Record every result in **0.3 As-Built-Record §11**.

## 4. What went wrong in the lab and how this phase prevents it

| # | Lab problem | Cause | Production prevention | Where |
|---|---|---|---|---|
| L1 | Service template deploy: "No suitable host" | Host not selected in the deployment preview | In Configure Deployment, every VM has a host with a rating, then **Refresh Preview** with no red message | 8.4, 8.7, 8.8 |
| L2 | "Application profile not compatible" | Microsoft SDN templates allow only WS2016 by default | Template: Application Configuration → **OS Compatibility** = WS2025; VM template **Operating System** = WS2025 Datacenter | 8.4, 8.7, 8.8 |
| L3 | Error **22655** "VMM unable to retrieve status" (NC, MUX and GW, every time) | **VMM Guest Agent** not installed (needs **Visual C++ x64**) | VC++ x64 baked into the SDN image. Manual fix kept in the troubleshooting tables | 8.2, 8.4 |
| L4 | NC setup script: "Path is null" on private key permissions | Certificate created with a **CNG/KSP** key | Certificate uses **Microsoft Enhanced RSA and AES Cryptographic Provider** (legacy CSP), exportable | 8.1 |
| L5 | NC setup script: `Get-ADGroup` not recognized | **RSAT-AD-PowerShell** missing | In the SDN image **and** the template's Roles and Features | 8.2, 8.4 |
| L6 | NC VM stuck on the Product Key screen | Template on WS2016 settings / image not evaluation | Guest OS profile uses the **WS2025 Datacenter AVMA key** | 8.4, 8.7, 8.8 |
| L7 | VHDX possibly copied before Sysprep finished | Ordering | Sysprep → VM off → check `Sysprep_succeeded.tag` → copy. Set OS on the VHDX in the library | 8.2 |
| L8 | Evaluation images shut down every hour | No online activation | Licensed media + AVMA | 1.1, 1.2 |
| L9 | VXLAN: small pings OK, `ping -f -l 1472` fails | MTU 1500 on the PA path | Jumbo end to end + **PA path jumbo test** in Gate 8.5 | 8.5 |
| L10 | Hosts didn't see HNV-PA | Site not in the uplink port profile | Add `HNV-PA_0` to `UPP-Converged` | 8.5 |
| L11 | Public VIP not advertised in BGP | No running backend behind it (the MUX withdraws VIPs without a healthy backend) | Test VIPs always have running backends. Noted in the SLB troubleshooting table | 8.7 |
| L12 | Load-balanced site always answered by the same VM | MUX balances per TCP connection, not per HTTP request | Test with new connections (`-DisableKeepAlive`) | 8.7 |
| L13 | IPsec tunnel Connected but no traffic | **Asymmetric routing**: client office IP was inside the GW's management subnet | The Management network never contains customer office/internet addresses. Gate: `Find-NetRoute` on each GW | 8.8 |
| L14 | Lost time diagnosing L13 | `pktmon` filter "ESP" matched "NONESP"; `Select -First` hid lines | Search `ESP\(spi`; don't truncate output | 8.8 |
| L15 | VMM refused an IP pool starting at `.1` on an NC-managed subnet | VMM reserves the first IP | Pools on NC-managed networks start at `.2`+; peers never use the first usable IP | 8.5, 8.6, 8.8 |
| L16 | Tunnel Connected but traffic failed after adding another connection | Stale IPsec SAs | After any connection change on a VM network, re-test all its connections; reconnect if needed | 8.8 |
| L17 | NAT wizard created a gateway without a NAT connection | OK pressed before the NAT tab was filled | Fill every tab, then **View Script** before OK | 8.8 |
| L18 | Port ACL with only Allow rules blocked nothing; ping failed but TCP worked | Default is Allow; ICMP not stateful | ACLs need an explicit Deny-All; test with TCP | 8.5 |
| L19 | `Get-SCNATConnection -VMNetworkGateway` returned nothing | Query method | Use the ID from View Script | 8.8 |
| L20 | Nested PowerShell Direct lost credentials | `$using:` doesn't pass through two hops | Pass credentials with `-ArgumentList` | 8.2, 8.4 |
| L21 | DC/host VM didn't start after a host stop (0xC035000A) | Saved state restored on a different CPU | `AutomaticStopAction ShutDown` for all infra and SDN VMs | 8.4, 8.7, 8.8 |

## 6. Nested PowerShell Direct pattern (L20)

Whenever a command runs **MGMT01 → host → VM**, pass the credential as an argument; `$using:` doesn't survive two hops:

```powershell
# MGMT01
$vmCred = Get-Credential "Administrator"
Invoke-Command -ComputerName HV01 -ArgumentList $vmCred -ScriptBlock {
    param($c)
    Invoke-Command -VMName "NC01" -Credential $c -ScriptBlock { hostname; Get-Service ScvmmGuestServiceV10 }
}
```

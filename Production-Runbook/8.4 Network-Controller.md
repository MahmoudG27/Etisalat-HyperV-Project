## 4. During deployment: method and troubleshooting

Keep a VM console of each NC open (Hyper-V Manager on MGMT01, enhanced session). When a job step fails:
1. **Jobs** → the failed step → read **Standard output / Error** (the script name tells you which phase failed).
2. Look inside the VM with PowerShell Direct (pattern from 8.0 §6, credentials passed with `-ArgumentList`, L20).
3. Fix the cause.
4. **Jobs → right-click the failed job → Restart**. Don't delete the service unless the table says so.

| Symptom | Cause | Fix |
|---|---|---|
| "No suitable host" at deploy (**L1**) | No host selected/rated in the preview | Configure Deployment → select a host per VM → **Refresh Preview** until no red message |
| "Application profile not compatible" (**L2**) | Template OS compatibility = WS2016 | §2: OS Compatibility + Operating System = WS2025 Datacenter, save, re-validate |
| Error **22655** "VMM unable to retrieve status" (**L3**) | VMM Guest Agent not installed (VC++ x64 missing) | Prevented by 8.2. Manual fix: copy `vcredist_x64.exe` and `vmmGuestAgent.msi` from `\\VMM01\C$\Program Files\Microsoft System Center\Virtual Machine Manager\agents\...` into the VM, install both, check service `ScvmmGuestServiceV10` is Running, then **Jobs → Restart** |
| NC script: "Path is null" on private key permissions (**L4**) | Certificate key is CNG/KSP | Re-issue per 8.1 (legacy CSP). Replace the PFX in `ServerCertificate.cr`, delete the failed service, redeploy |
| NC script: `Get-ADGroup` not recognized (**L5**) | RSAT-AD-PowerShell missing | Prevented by 8.2/§2. Manual: `Install-WindowsFeature RSAT-AD-PowerShell` in the VM, **Jobs → Restart** |
| VM stuck at Product Key screen (**L6**) | No/invalid key in the guest OS profile | §2 product key = WS2025 Datacenter AVMA. Manually: enter the AVMA key in the console |
| Deployment fails and can't be restarted | – | **VMs and Services → Services → NC → Delete**, fix the cause, redeploy |

## 5. After deployment: SPN rights, OU, anti-affinity, stop action

**SPN** (Windows Server 2019+: the NC nodes must be allowed to register their SPN, or VMM's Kerberos REST calls fail):

```powershell
# DC01
$ncNodes = "NC01","NC02","NC03"
foreach ($target in $ncNodes) {
    $dn = (Get-ADComputer $target).DistinguishedName
    foreach ($node in $ncNodes) {
        dsacls $dn /G "ETISALAT\$($node)`$:WS;Validated write to service principal name"
        dsacls $dn /G "ETISALAT\$($node)`$:RPWP;servicePrincipalName"
    }
}
$ncNodes | ForEach-Object { Get-ADComputer $_ | Move-ADObject -TargetPath "OU=SDN,OU=Infrastructure,DC=etisalat,DC=local" }
setspn -Q "HTTP/ncrest.etisalat.local"      # appears within minutes; restart NC nodes one at a time if not
```

**Stop action (L21):**

```powershell
# MGMT01
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock {
    Get-VM | Where-Object Name -match '^(NC|MUX|GW)\d' | Set-VM -AutomaticStopAction ShutDown
}
```

**Anti-affinity: check only.** The VMM availability set `AS-SDN-NC` (§2) already writes the cluster group's `AntiAffinityClassNames`. Don't set it by hand: a manual value overwrites what VMM wrote, and VMM and the cluster can end up disagreeing.

```powershell
# HV01 (cluster node)
Get-ClusterGroup NC0* | Format-Table Name, OwnerNode, AntiAffinityClassNames      # expect AS-SDN-NC on all three
```

> **Fallback, only if the value is empty after deployment:** set it manually to the availability-set name.
> `$ac = New-Object System.Collections.Specialized.StringCollection; [void]$ac.Add("AS-SDN-NC"); (Get-ClusterGroup NC01).AntiAffinityClassNames = $ac` (repeat per VM).
> Then re-check in VMM (VM → Properties → Hardware Configuration → Availability) that the VM still shows availability set `AS-SDN-NC`.

## 7. NC backup: one scheduled task (added to 6.5)

Microsoft's procedure ("Upgrade, backup, and restore SDN infrastructure"):
1. Back up the NC VMs (they carry the certificates needed to decrypt the backup).
2. **Stop the VMM service** and back up the VMM DB **via SQL Server**.
3. Run `New-NetworkControllerBackup` and check it with `Get-NetworkControllerBackup`.
4. Start VMM again.

While `SCVMMService` is stopped, **VMM jobs fail**. So the whole sequence is **one scheduled task on VMM01**, in a short agreed window:

| Order | Step | Why |
|---|---|---|
| 1 | Stop `SCVMMService` | No VMM changes during the NC backup (Microsoft) |
| 2 | SQL full backup of `VirtualManagerDB` → SQL01 `B:\VMMBackup` | DB copy consistent with the NC backup. `Backup-SCVMMServer` can't be used here: it needs the VMM service **running** |
| 3 | `New-NetworkControllerBackup` → `<BACKUP-SHARE>\NC\<timestamp>` | NC database |
| 4 | Wait for `ProvisioningState = Succeeded` (max 25 min) | – |
| 5 | Start `SCVMMService` (always, also on failure) | VMM back in service |

**Schedule:** daily at **01:30** (placeholder), **before** the 6.5 VMM task (02:00). The 02:00 task waits until `SCVMMService` is running before `Backup-SCVMMServer` (6.5 §4), so the two never overlap. Frequency and window: **daily (placeholder), agree the window with Etisalat** (0.2 §1 #25 maintenance window).

**Accounts:**
- `svc-ncbackup` (4.2, vault `NC-Backup`) is the **share** credential the NC nodes use to write to `<BACKUP-SHARE>\NC`.
- The task runs as **`svc-vmm`**. It's local admin on VMM01 (to stop/start the service), a member of `DL-NC-Users` (4.2, for NC REST via Kerberos), and must be able to back up `VirtualManagerDB` on SQL01 (`db_backupoperator`/`db_owner`, *to be verified*).

Once: store the share credential inside NC.

```powershell
# MGMT01 (RSAT-NetworkController)
$uri  = "https://ncrest.etisalat.local"
$cred = Get-Credential "ETISALAT\svc-sdn"                      # NC REST credential (DL-NC-Users)
$p = New-Object Microsoft.Windows.NetworkController.CredentialProperties
$p.Type = "usernamePassword"; $p.UserName = "ETISALAT\svc-ncbackup"; $p.Value = "<password from vault: NC-Backup>"
New-NetworkControllerCredential -ConnectionUri $uri -Credential $cred -Properties $p -ResourceId "BackupUser" -Force
```

Once: the task on VMM01.

```powershell
# VMM01
Install-WindowsFeature RSAT-NetworkController
New-Item -ItemType Directory -Path C:\Scripts -Force | Out-Null
@'
$ErrorActionPreference = "Stop"
$uri = "https://ncrest.etisalat.local"                      # NC REST; identity = task account (svc-vmm, DL-NC-Users)
$t   = (Get-Date).ToString("s").Replace(":", "_")
Start-Transcript -Path "C:\Scripts\Logs\Backup-NC-VMM_$t.log"
try {
    Stop-Service SCVMMService
    sqlcmd -S SQL01 -E -b -Q "BACKUP DATABASE [VirtualManagerDB] TO DISK = N'B:\VMMBackup\VirtualManagerDB_NCwindow_$t.bak' WITH COMPRESSION, CHECKSUM, INIT"
    if ($LASTEXITCODE -ne 0) { throw "VMM DB SQL backup failed ($LASTEXITCODE)" }

    $shareCred = Get-NetworkControllerCredential -ConnectionUri $uri -ResourceId "BackupUser"
    $bp = New-Object Microsoft.Windows.NetworkController.NetworkControllerBackupProperties
    $bp.BackupPath = "<BACKUP-SHARE>\NC\$t"; $bp.Credential = $shareCred
    New-NetworkControllerBackup -ConnectionUri $uri -Properties $bp -ResourceId $t -Force | Out-Null

    $deadline = (Get-Date).AddMinutes(25)
    do { Start-Sleep -Seconds 30
         $state = (Get-NetworkControllerBackup -ConnectionUri $uri -ResourceId $t).Properties.ProvisioningState
    } until ($state -in "Succeeded","Failed" -or (Get-Date) -gt $deadline)
    if ($state -ne "Succeeded") { throw "NC backup $t ended in state '$state'" }
    "NC backup $t Succeeded"
}
finally {
    Start-Service SCVMMService
    Stop-Transcript
}
'@ | Set-Content C:\Scripts\Backup-NC-VMM.ps1
New-Item -ItemType Directory -Path C:\Scripts\Logs -Force | Out-Null

$a = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-NoProfile -ExecutionPolicy Bypass -File C:\Scripts\Backup-NC-VMM.ps1"
$tr = New-ScheduledTaskTrigger -Daily -At 01:30
Register-ScheduledTask -TaskName "BKP - NC + VMM DB" -Action $a -Trigger $tr -User "ETISALAT\svc-vmm" -Password (Read-Host "svc-vmm password") -RunLevel Highest -Force
Start-ScheduledTask -TaskName "BKP - NC + VMM DB"      # first run now, during an agreed window
```

- The VMM DB `.bak` lands on SQL01 `B:\VMMBackup` and is copied off-cluster by the 6.5 SQL job (03:00).
- If `svc-vmm`'s password is rotated, re-register this task (same rule as 6.5).

Check a run:

```powershell
# MGMT01
$uri  = "https://ncrest.etisalat.local"
$cred = Get-Credential "ETISALAT\svc-sdn"
Get-NetworkControllerBackup -ConnectionUri $uri -Credential $cred | Sort-Object ResourceId | Select-Object -Last 3 |
    ForEach-Object { "$($_.ResourceId)  $($_.Properties.ProvisioningState)  $($_.Properties.ErrorMessage)" }
```

# 1.1 Hosts baseline + SET switch (HV01, HV02, HV03, HV04)

> Replaces `1. FirstStep.md`. Run on **each** host from the **iLO / iDRAC console**. The network changes in this file will drop any RDP/remote session.

## 0. Before installing Windows (hardware checklist)

- [ ] Latest BIOS / firmware / NIC / HBA firmware from the vendor (Dell SUU / HPE SPP / Lenovo XClarity), **identical on all 4 hosts**.
- [ ] BIOS: Virtualization (VT-x / AMD-V) **On**, VT-d / IOMMU **On**, Power profile = **Maximum performance**, Secure Boot **On**, TPM 2.0 **On**.
- [ ] Local RAID volumes: `C:` for the OS (RAID1) and, if present, a second local volume `D:` used only for DC01/DC02 (RAID1/5). If there's no D:, use `C:\VMs` everywhere instead of `D:\VMs`.
- [ ] Write down the MAC address of each port, and which physical switch port it's cabled to (needed for step 2).
- [ ] Hardware matches the answers in 0.2 §8 (≥ 4 data ports, core count for licensing).
- [ ] **Licensed media + Datacenter product key/activation method** received from Etisalat (0.2 §9). **No Evaluation media**: an evaluation host that can't activate online shuts itself down every hour.

## 3. Time zone, power plan, rename NICs

```powershell
# HV01–HV04 (each host)
Set-TimeZone -Id "Egypt Standard Time"

# Identify the NICs (match the MACs with your cabling sheet)
Get-NetAdapter | Sort-Object MacAddress | Format-Table Name, InterfaceDescription, MacAddress, LinkSpeed, Status
```

Rename the adapters by MAC. **Replace the MACs** with the real ones from the output above.

```powershell
$map = @{
  "AA-BB-CC-00-00-01" = "NIC1"   # port 1 -> switch A (trunk)
  "AA-BB-CC-00-00-02" = "NIC2"   # port 2 -> switch B (trunk)
  "AA-BB-CC-00-00-03" = "NIC3"   # iSCSI-A
  "AA-BB-CC-00-00-04" = "NIC4"   # iSCSI-B
}
foreach ($mac in $map.Keys) { Get-NetAdapter | Where-Object MacAddress -eq $mac | Rename-NetAdapter -NewName $map[$mac] }

# Disable any unused/onboard ports, so cluster validation doesn't complain about them.
# If a server has more than 4 data ports, the extra ports stay disabled too. The design uses exactly NIC1–NIC4.
Get-NetAdapter | Where-Object { $_.Name -notin "NIC1","NIC2","NIC3","NIC4" } | Disable-NetAdapter -Confirm:$false

Get-NetAdapter | Sort-Object Name | Format-Table Name, InterfaceDescription, MacAddress, LinkSpeed, Status
```

## 5. Jumbo frames on the physical NICs (required)

> **Required, on both sides.** The network team sets MTU 9216 on the switch side (0.2 §3). We set it on the hosts.
> Why: iSCSI performance, Live Migration, and the VXLAN overhead on HNV-PA (Microsoft minimum 1674 on the PA path).
> Customer VMs stay at MTU 1500.

```powershell
# HV01–HV04 (each host)
# 1. Check the valid value for this NIC driver first (9014 on most drivers, 9000 on some)
Get-NetAdapterAdvancedProperty -RegistryKeyword "*JumboPacket" | Select-Object Name, DisplayValue, ValidDisplayValues

# 2. Set it (use 9000 instead if that's what ValidDisplayValues shows)
Set-NetAdapterAdvancedProperty -Name "NIC1","NIC2","NIC3","NIC4" -RegistryKeyword "*JumboPacket" -RegistryValue 9014
```

The host vNIC `vEthernet (LiveMigration)` gets the same setting right after it's created (§6).

## 6. SET switch on NIC1 + NIC2

```powershell
# HV01–HV04 (each host)
New-VMSwitch -Name $Switch -NetAdapterName "NIC1","NIC2" -EnableEmbeddedTeaming $true -AllowManagementOS $false -MinimumBandwidthMode Weight
Set-VMSwitchTeam -Name $Switch -LoadBalancingAlgorithm HyperVPort
Set-VMSwitch -Name $Switch -DefaultFlowMinimumBandwidthWeight 50

# Host virtual NICs
Add-VMNetworkAdapter -ManagementOS -SwitchName $Switch -Name "Management"
Add-VMNetworkAdapter -ManagementOS -SwitchName $Switch -Name "LiveMigration"

Set-VMNetworkAdapterVlan -ManagementOS -VMNetworkAdapterName "Management"    -Access -VlanId 100
Set-VMNetworkAdapterVlan -ManagementOS -VMNetworkAdapterName "LiveMigration" -Access -VlanId 101

Set-VMNetworkAdapter -ManagementOS -Name "Management"    -MinimumBandwidthWeight 10
Set-VMNetworkAdapter -ManagementOS -Name "LiveMigration" -MinimumBandwidthWeight 30

# IPs
New-NetIPAddress -InterfaceAlias "vEthernet (Management)" -IPAddress $MgmtIP -PrefixLength 24 -DefaultGateway $Gateway
Set-DnsClientServerAddress -InterfaceAlias "vEthernet (Management)" -ServerAddresses $DnsSrv

New-NetIPAddress -InterfaceAlias "vEthernet (LiveMigration)" -IPAddress $LMIP -PrefixLength 24
Set-DnsClient -InterfaceAlias "vEthernet (LiveMigration)" -RegisterThisConnectionsAddress $false

# Jumbo on the Live Migration host vNIC (same value as the physical NICs in §5)
Set-NetAdapterAdvancedProperty -Name "vEthernet (LiveMigration)" -RegistryKeyword "*JumboPacket" -RegistryValue 9014
```

**Why it's built exactly like this:**
- Both NICs carry traffic, so losing one cable or switch doesn't disconnect the host or its VMs.
- The switch name, uplink mode (Embedded Team), load balancing (Hyper-V Port) and bandwidth mode (Weight) match the VMM logical switch built in 6.4. VMM can then **convert** it in place, without recreating it (0.1 D1). **Don't change these values.**
- The same switch name exists on all 4 hosts, so DC/SQL/VMM VMs can run on and live-migrate to any host.

## 9. Windows Update

The hosts aren't in the domain yet, so no GPO applies. Set the update source locally (0.2 §1 #17).

```powershell
# HV01–HV04 (each host) – only if a proxy is used (0.2 §1 #17 b)
```

If WSUS is used instead (0.2 §1 #17 a), the hosts pick it up from the `SRV - Update Source` GPO after joining the domain (2.1 §7, 3.1). For this first pass, use the proxy, or patch after 3.1.

## 10. Activate Windows (Datacenter)

Every host **must** be activated. AVMA guest activation (1.2) only works on an activated Datacenter host, and in a cluster **each** node must be activated for guests to stay activated wherever they run.

```powershell
# HV01–HV04 (each host) – option A: MAK / retail key from Etisalat's licensing (placeholder)
cscript //nologo C:\Windows\System32\slmgr.vbs /ipk XXXXX-XXXXX-XXXXX-XXXXX-XXXXX
cscript //nologo C:\Windows\System32\slmgr.vbs /ato

# HV01–HV04 (each host) – option B: Etisalat KMS host (volume media already carries the KMS client key)
cscript //nologo C:\Windows\System32\slmgr.vbs /skms <kms-host-from-0.2>:1688
cscript //nologo C:\Windows\System32\slmgr.vbs /ato
```

- MAK activation needs a path to Microsoft's activation service (proxy). If the management network has none, use **phone activation** (`slui 4`), or option B.
- The key is a placeholder until Etisalat answers 0.2 §9.

## 11. Antivirus (only if Etisalat enforces an AV product)

If a non-Microsoft antivirus is enforced, apply Microsoft's **"Recommended antivirus exclusions for Hyper-V hosts"** and **"Antivirus exclusions for VMM and managed hosts"**.
Well-known items:
- Folders: the VM/VHDX folders (`D:\VMs`, later `C:\ClusterStorage`), `%ProgramData%\Microsoft\Windows\Hyper-V`.
- Processes: `Vmms.exe`, `Vmwp.exe`, `Vmsp.exe`, `Vmcompute.exe`.

Microsoft Defender on Windows Server applies the Hyper-V role exclusions automatically.
Cluster/CSV exclusions are added in 5.2.

Jumbo end-to-end tests (8972 bytes + 28 header = 9000, `-f` = don't fragment):

```powershell
# HV01 (repeat from each host towards another host)
ping -f -l 8972 10.10.101.12          # HV02 LiveMigration IP
ping -f -l 8972 10.10.110.201         # SAN iSCSI-A portal IP
ping -f -l 8972 10.10.111.201         # SAN iSCSI-B portal IP
```

> The two SAN pings need the SAN iSCSI ports configured. If they aren't ready yet, they're repeated in Gate 5.1.
> The HNV-PA path test is done later, in the SDN phase.

Expected:
- `EmbeddedTeamingEnabled = True`, `BandwidthReservationMode = Weight`, `IovEnabled = False`.
- Management VLAN 100, LiveMigration VLAN 101.
- `*JumboPacket` = 9014 (or 9000) on NIC1–NIC4 and `vEthernet (LiveMigration)`.
- Gateway reachable. All three jumbo pings reply. "Packet needs to be fragmented but DF set" means a hop is still at 1500: send that to the network team.
- `slmgr /dli` shows **License Status: Licensed** (not "Notification" or "Initial grace period").
- `CurrentBuild` + `UBR` identical on all 4 hosts. Write it down: it's the reference build for all VMs.

Unplug NIC1 for a moment: the management ping must keep working. Plug it back, then unplug NIC2 and test again.

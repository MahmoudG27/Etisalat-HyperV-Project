# 8.9 SDN operations baseline + final SDN acceptance

> Last file of the SDN fabric phase. After its Gate, the fabric is ready for the customer onboarding phase (written later).

## 1. Placement / anti-affinity summary

| Group | VMs | Clustered | Mechanism | CAU (6.6) behaviour |
|---|---|---|---|---|
| NC | NC01–NC03 | Yes | `AntiAffinityClassNames = SDN-NC` + VMM availability set `AS-SDN-NC` | Drained one node at a time → only one NC moves. NC cluster keeps quorum (2 of 3 Up) |
| MUX | MUX01–MUX02 | Yes | `SDN-MUX` + `AS-SDN-MUX` | One MUX live-migrates at a time. The other keeps advertising the VIPs (ECMP) |
| GW | GW01–GW02 | **No** (8.8 §1) | Placed on two different hosts at deployment | The GW on the drained host **shuts down** with it. NC fails over to the standby once. After the reboot it returns as standby |
| DC | DC01, DC02 | No | Local disks of HV01/HV02 | One DC at a time (6.6 §2) |

```powershell
# HV01 (cluster node) – monthly placement check
Get-ClusterGroup | Where-Object Name -match '^(NC|MUX)\d' | Format-Table Name, OwnerNode, State, AntiAffinityClassNames
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock { Get-VM | Where-Object Name -match '^GW\d' | Select-Object Name, State, AutomaticStopAction }
```

**Before each CAU run:**
- Check which GW is **active** (8.8 §7c).
- Make sure no two NC or two MUX share a host.
- Microsoft's update order for SDN:
  1. Management consoles.
  2. NC VMs, one at a time, waiting for `Up` (`Get-NetworkControllerNode`).
  3. MUX one at a time.
  4. Hosts + gateways, starting with the hosts that run the **standby** GW.

  CAU automates the host part. Patch the NC/MUX/GW guests with `Update-GuestWindows` in that order.

## 2. Backups (added to 6.5)

| What | How | Frequency | Target |
|---|---|---|---|
| NC database | `New-NetworkControllerBackup` (8.4 §7), with the VMM service stopped and the VMM DB backed up in the same window, then `Get-NetworkControllerBackup` = Succeeded | Daily (placeholder) | `<BACKUP-SHARE>\NC\<timestamp>` |
| NC VMs | VM-level backup or Hyper-V export (they hold the certificates needed to decrypt the NC backup) | Weekly + before changes | `<BACKUP-SHARE>\NC-VMs` |
| NC certificate | `ncrest.pfx` + password | On issue/renewal | **Vault** entry `NC-PFX` (+ offline copy per Etisalat policy) |
| Etisalat CA chain | `etisalat-root.cer`, `etisalat-int.cer` | On change | Vault / `<BACKUP-SHARE>\PKI` |

Restore order (Microsoft):
1. Hosts and storage.
2. NC, MUX and GW VMs.
3. Stop `SlbHostAgent`/`NcHostAgent` on the hosts, and stop the GW and MUX VMs.
4. `New-NetworkControllerRestore`.
5. Restore the VMM DB from the **same** window.
6. Run `Debug-NetworkControllerConfigurationState`.

## 3. Certificate expiry

- NC certificate **NotAfter** = `<date>` (0.3 §11). Calendar reminder **60 days before**, owners: Etisalat PKI + platform team.
- Renewal procedure for the NC REST certificate in VMM 2025: **to be written / verified in a lab** before the first expiry (8.1 §8).
- Check monthly:

```powershell
# MGMT01 – expiry date of the certificate NC presents on 443
$tcp = New-Object Net.Sockets.TcpClient("ncrest.etisalat.local", 443); $ssl = New-Object Net.Security.SslStream($tcp.GetStream())
$ssl.AuthenticateAsClient("ncrest.etisalat.local"); $ssl.RemoteCertificate.GetExpirationDateString(); $tcp.Close()
```

## 4. Monthly health checks

```powershell
# MGMT01
$uri  = "https://ncrest.etisalat.local"; $cred = Get-Credential "ETISALAT\svc-sdn"

# NC nodes
Invoke-Command -ComputerName NC01 -ScriptBlock { Get-NetworkControllerNode | Format-Table Name, Status }

# Host agents + VFP
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock {
    "$env:COMPUTERNAME  NcHostAgent=$((Get-Service NcHostAgent).Status)  SlbHostAgent=$((Get-Service SlbHostAgent).Status)"
}

# Servers / MUX / gateways configuration state as seen by NC
Get-NetworkControllerServer           -ConnectionUri $uri -Credential $cred | ForEach-Object { "$($_.ResourceId)  $($_.Properties.ConfigurationState.Status)" }
Get-NetworkControllerLoadBalancerMux  -ConnectionUri $uri -Credential $cred | ForEach-Object { "$($_.ResourceId)  $($_.Properties.ConfigurationState.Status)" }
Get-NetworkControllerGateway          -ConnectionUri $uri -Credential $cred | ForEach-Object { "$($_.ResourceId)  $($_.Properties.State)" }

# Whole-fabric configuration check (Microsoft)
Debug-NetworkControllerConfigurationState -NetworkController $uri -Credential $cred
```

| Check | Expected | Owner |
|---|---|---|
| NC nodes | 3 × Up | Platform |
| Host agents | Running on all hosts | Platform |
| NC configuration state (servers, MUX, gateways) | Success, no errors from `Debug-NetworkControllerConfigurationState` | Platform |
| BGP sessions (MUX × 2, GW × 2) | Established | Etisalat network team |
| VIP advertisement | Every in-use VIP /32 present via both MUX | Etisalat network team |
| NC backup | Last `ProvisioningState = Succeeded` < 24 h | Platform |
| Certificate | > 60 days left | Platform + PKI |
| Placement | §1 rules respected | Platform |

Optional tooling: `Install-Module SdnDiagnostics` on MGMT01 (Microsoft SDN diagnostics module) for deeper fabric health reports.

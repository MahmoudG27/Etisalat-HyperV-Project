## 2. Design decisions taken in this runbook

1. **NIC1 + NIC2 → one SET switch named `LS-Converged`** on all 4 hosts (same name everywhere, so VMs can live-migrate).
   Host vNICs: `Management` (VLAN 100) and `LiveMigration` (VLAN 101). VMs (DC/SQL/VMM/NC/tenants) connect to the same switch with their own VLAN.
   Later, VMM **converts** this switch into the Logical Switch `LS-Converged`. VMM 2025 supports converting a standard/SET switch with no traffic interruption, so nothing is rebuilt (how it works: 0.1 D1).
   Management VMs can run on any of the 4 hosts.
2. **NIC3 / NIC4 → iSCSI only**, two separate subnets (iSCSI-A, iSCSI-B), no gateway, no team, no vSwitch. MPIO provides redundancy.
3. **DC01 on HV01 local disk, DC02 on HV02 local disk.** They aren't clustered, auto-start with the host, and keep AD alive even if the cluster/SAN is down.
4. **SQL01, VMM01, MGMT01 (jump server), NC01-03** are **highly available VMs on the CSV**.
5. **VMM: one VMM server + one SQL Server 2022** (approved), both as HA VMs (a host failure is covered by the cluster). DKM is stored in AD from day 1. SQL Always On / VMM HA remain optional future steps (7.1 / 7.2).
   OS/edition per role: see 0.1 D4.
6. **Network Controller: 3-node VM-based NC, deployed by VMM from Microsoft's service template** ("Network Controller Production Generation 2 VM").
   *Note:* Windows Server 2025 can also run NC as a Failover-Cluster role (no VMs), but that's deployed with SDN Express/WAC, **not** by VMM. You want VMM to own NC, so VM-based NC is used here.
7. **CSV = NTFS 64K**, witness = disk witness on a small LUN.
8. **Copy/paste into VMs**: Enhanced Session Mode on every host + Guest Service Interface on every VM + Desktop Experience guests. Details in 1.2.

**Domain:** `etisalat.local` / NetBIOS `ETISALAT` (kept as in your docs).
For a brand-new forest, Microsoft recommends a subdomain of a domain you own (for example `corp.<company>.com`) instead of `.local`. Decide **before** step 2.1. It can't be changed later.

**Physical switch requirements (send to the network team before day 1):**
- NIC1/NIC2 ports: **trunk**, allowed VLANs 100, 101, 200 + tenant VLANs. MTU **9216**. No LACP/port-channel (SET is switch-independent).
- NIC3 ports: access VLAN 110. NIC4 ports: access VLAN 111. MTU 9216. Ideally on two different physical switches.
- VLAN 200 (HNV PA) must be routed (gateway 10.10.200.1), and its MTU must be ≥ 1674 end to end (VXLAN overhead). Jumbo frames cover this.

# 6.3 VMM fabric: Run As accounts → host firewall → host groups → add HVCL01

> Run on **MGMT01**: VMM console, or **VMM PowerShell** (`Import-Module VirtualMachineManager`).
> Prerequisite: 6.2 Gate passed (VMM01 running, console connects).
> The order in this file is fixed. VMM must manage the hosts (end of this file) before the switch conversion in 6.4.
> Tip: every VMM wizard has a **View Script** button. Save the script it shows; that's your exact, reproducible change log.

```powershell
# MGMT01 (VMM PowerShell) – run once per session
Import-Module VirtualMachineManager
Get-SCVMMServer -ComputerName VMM01.etisalat.local | Out-Null
```

## 1. Run As accounts

| Name | Account | Used for | "Validate domain credentials" |
|---|---|---|---|
| `RA-HostAdmin` | `ETISALAT\svc-vmm-ras` | Add/manage Hyper-V hosts + cluster. Member of `GG-HyperV-HostAdmins` = local admin on HV01–HV04 (4.2) | ✔ |

SDN Run As accounts (`RA-SDN`, `RA-NC-LocalAdmin`) are created in the SDN phase.

Console: **Settings → Security → Run As Accounts → Create Run As Account**.

```powershell
# MGMT01 (VMM PowerShell)
New-SCRunAsAccount -Name "RA-HostAdmin" -Credential (Get-Credential "ETISALAT\svc-vmm-ras") -Description "Hyper-V hosts and clusters management"
Get-SCRunAsAccount | Format-Table Name, UserName, Domain
```

## 2. Firewall rules on every cluster node (so VMM can reach them)

The VMM agent is pushed over SMB and managed over WMI/WinRM. 1.1 §8 already enables these. Re-apply and verify from MGMT01, in case a GPO or a rebuild changed them:

```powershell
# MGMT01
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock {
    Enable-NetFirewallRule -DisplayGroup "File and Printer Sharing"
    Enable-NetFirewallRule -DisplayGroup "Windows Management Instrumentation (WMI)"
}

# MGMT01 – verify
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock {
    Get-NetFirewallRule -DisplayGroup "File and Printer Sharing","Windows Management Instrumentation (WMI)" |
        Where-Object { $_.Enabled -eq 'True' -and $_.Profile -match 'Domain|Any' } |
        Measure-Object | Select-Object @{n='Host';e={$env:COMPUTERNAME}}, Count
}
"HV01","HV02","HV03","HV04" | ForEach-Object { Test-NetConnection $_ -Port 445 -InformationLevel Quiet; Test-NetConnection $_ -Port 5985 -InformationLevel Quiet }
```

Expected: every host has enabled rules (Count > 0), and ports 445 (SMB) and 5985 (WinRM) answer `True`.

## 3. Host groups

```
All Hosts
└── Etisalat-DC
    ├── Cluster1      (HVCL01 – 4 new hosts, management + first customers)
    └── Cluster2      (HVCL02 – the 12 converted ESXi hosts, empty for now)
```

Console: **Fabric → Servers → All Hosts → right-click → Create Host Group**.

```powershell
# MGMT01 (VMM PowerShell)
$dc = New-SCVMHostGroup -Name "Etisalat-DC"
New-SCVMHostGroup -Name "Cluster1" -ParentHostGroup $dc
New-SCVMHostGroup -Name "Cluster2" -ParentHostGroup $dc
Get-SCVMHostGroup | Format-Table Name, Path
```

Logical network sites in 6.4 are scoped to **`Etisalat-DC`**, so both clusters inherit them. In the SDN phase, the Network Controller will also manage `Etisalat-DC`.

## 4. Add the existing cluster HVCL01 to VMM

The cluster was built in 5.2 (before VMM existed). VMM **adds** it, it doesn't create it.

Console: **Fabric → Servers → All Hosts → Etisalat-DC → Cluster1** → right-click → **Add Hyper-V Hosts and Clusters**:

| Page | Value |
|---|---|
| Resource location | **Windows Server computers in a trusted Active Directory domain** |
| Credentials | Run As account **`RA-HostAdmin`** |
| Discovery scope | Specify computer names: **`HVCL01`** |
| Target resources | Select the **cluster HVCL01** (HV01–HV04 come with it). Don't tick "Reassociate this host with this VMM environment" |
| Host settings | Host group **`Etisalat-DC\Cluster1`**. Keep the default VM placement paths (the CSV paths from 5.2) |
| Summary | Finish. The job installs the VMM agent on HV01–HV04 (5–10 min) |

PowerShell equivalent:

```powershell
# MGMT01 (VMM PowerShell)
$hg  = Get-SCVMHostGroup -Name "Cluster1"
$ras = Get-SCRunAsAccount -Name "RA-HostAdmin"
Add-SCVMHostCluster -Name "HVCL01.etisalat.local" -VMHostGroup $hg -Credential $ras
```

Recommended after the job:

```powershell
# MGMT01 (VMM PowerShell)
Set-SCVMHostCluster -VMHostCluster (Get-SCVMHostCluster -Name "HVCL01.etisalat.local") -ClusterReserve 1   # warn before placing more than 3 hosts can carry
```

Host **Properties → Host Reserves**: keep at least 4 GB RAM / 10 % CPU for the parent partition.

## 5. Library folders

The library share `\\VMM01\MSSCVMMLibrary` is added automatically during VMM setup.

```powershell
# MGMT01
"ISO","VHDs","Scripts" | ForEach-Object { New-Item -ItemType Directory -Path "\\VMM01\MSSCVMMLibrary\$_" -Force }
```

```powershell
# MGMT01 (VMM PowerShell)
Get-SCLibraryShare | Read-SCLibraryShare        # refresh
```

Copy `WindowsServer2025.iso` into `\ISO`.

DC01, DC02, SQL01, VMM01 and MGMT01 now appear under **VMs and Services** automatically. Don't delete or recreate them. Their network settings are attached to VMM objects in 6.4 §7.

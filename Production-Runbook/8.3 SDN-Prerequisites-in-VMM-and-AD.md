# 8.3 SDN prerequisites in VMM and AD

> Everything the Microsoft SDN templates reference must exist before 8.4: Run As accounts, AD groups and rights, the REST DNS record, the templates and their custom resources in the library.

## 1. AD: groups, accounts, rights

The groups and `svc-sdn` were created in 4.2. Microsoft's requirements (VMM "Set up an SDN network controller"):

| Object | Requirement | Our value |
|---|---|---|
| NC **management** security group (`MgmtSecurityGroup`) | **Domain Local**. Members can configure NC. Must contain the `MgmtDomainAccount` | `DL-NC-Admins` ∋ `svc-sdn` |
| NC **clients** security group (`ClientSecurityGroup`) | **Domain Local**. Members can talk to NC REST. Must contain the account used by the **network service** in VMM | `DL-NC-Users` ∋ `svc-sdn` |
| Members | Must also be members of **Domain Users** | default |
| VMM service account / admins | Whether `svc-vmm` or `GG-VMM-Admins` must also be in `DL-NC-Users` isn't stated in the VMM docs. The network service uses the Run As credential (`RA-SDN`) → **to be verified**: add only if the 8.4 "Add Network Service" step fails with access denied | – |

```powershell
# DC01 (or MGMT01 with RSAT-AD-Tools)
Get-ADGroup DL-NC-Admins, DL-NC-Users | Select-Object Name, GroupScope              # DomainLocal
Get-ADGroupMember DL-NC-Admins; Get-ADGroupMember DL-NC-Users                         # svc-sdn in both

# svc-sdn may create/join computer objects in OU=SDN (SDN VMs are joined by the templates)
$ou = "OU=SDN,OU=Infrastructure,DC=etisalat,DC=local"
dsacls $ou /I:T /G "ETISALAT\svc-sdn:CC;computer"
dsacls $ou /I:S /G "ETISALAT\svc-sdn:GA;;computer"
```

> The templates join the VMs into the default **Computers** container. Move them to `OU=SDN` after each deployment (8.4/8.7/8.8). Alternatively pre-stage `NC01..03`, `MUX01..02`, `GW01..02` in `OU=SDN` and grant `svc-sdn` rights on them.

**REST DNS record** (the 3 NC nodes are in the same subnet, so REST uses a static IP, VMM doc):

```powershell
# DC01
Add-DnsServerResourceRecordA -ZoneName "etisalat.local" -Name "ncrest" -IPv4Address 10.10.100.50 -CreatePtr
Resolve-DnsName ncrest.etisalat.local
```

## 2. Run As accounts in VMM

| Run As | Account | Used for | Validate domain credentials |
|---|---|---|---|
| `RA-SDN` | `ETISALAT\svc-sdn` | NC `MgmtDomainAccount`, SLB/GW domain join (`MgmtDomainAccount` / `Management Account`), **network service** credential, Gateway Manager role | ✔ |
| `RA-NC-LocalAdmin` | `Administrator` (local, password in vault: `SDN-LocalAdmin`) | `LocalAdmin` / `AdminAccount` inside NC, MUX, GW | ✘ (local account) |

```powershell
# MGMT01 (VMM PowerShell)
New-SCRunAsAccount -Name "RA-SDN"           -Credential (Get-Credential "ETISALAT\svc-sdn")
New-SCRunAsAccount -Name "RA-NC-LocalAdmin" -Credential (Get-Credential "Administrator") -NoValidation
Get-SCRunAsAccount | Format-Table Name, UserName, Domain
```

## 3. Microsoft SDN templates into the library

```powershell
# MGMT01 (internet through the proxy, or download elsewhere and copy)
Invoke-WebRequest "https://github.com/microsoft/SDN/archive/refs/heads/master.zip" -OutFile C:\Install\SDN.zip
Expand-Archive C:\Install\SDN.zip -DestinationPath C:\Install\SDN -Force
$src = "C:\Install\SDN\SDN-master\VMM\Templates"
"NC","SLB","GW" | ForEach-Object { Copy-Item "$src\$_" "\\VMM01\MSSCVMMLibrary\SDN\$_" -Recurse -Force }
Get-ChildItem "\\VMM01\MSSCVMMLibrary\SDN" -Recurse -Depth 1 | Select-Object FullName
```

Content of the Microsoft repository (`VMM\Templates`) and what this runbook uses:

| Folder | Files | Used |
|---|---|---|
| NC | `Network Controller Production Generation 2 VM.xml` (+ Gen1, Standalone Gen1/Gen2) | **Production Gen2** (8.4) |
| NC | `NCSetup.cr`, `ServerCertificate.cr`, `NCCertificate.cr`, `TrustedRootCertificate.cr`, `EdgeDeployment.cr` | All (custom resources) |
| SLB | `SLB Production Generation 2 VM - Simplified.xml` (+ Gen2 non-simplified, Gen1 variants) | **Gen2 Simplified** (8.7) |
| GW | `EdgeServiceTemplate_Generation2.xml` (+ Gen1) | **Generation2** (8.8) |

## 4. Custom resources: what goes where

| Custom resource (library folder) | Referenced by | Content to place | Rule |
|---|---|---|---|
| `NCSetup.cr` | NC template | Microsoft's scripts (as downloaded) | Don't modify |
| `ServerCertificate.cr` | NC template | `ncrest.pfx` (8.1) | **Exactly one** .pfx in the folder |
| `NCCertificate.cr` | NC template, SLB template | `ncrest-public.cer` (NC cert **without** private key, Base-64) | – |
| `TrustedRootCertificate.cr` | NC template | `etisalat-root.cer` (CA public key) | Required for a CA-issued cert. Whether the **intermediate** may also be placed here is *to be verified*. The PFX already carries the chain (`-ChainOption BuildChain`) and the GPO distributes the intermediate |
| `EdgeDeployment.cr` | SLB and GW templates | Microsoft's scripts (as downloaded) | Don't modify |

```powershell
# MGMT01
$lib = "\\VMM01\MSSCVMMLibrary\SDN\NC"
Copy-Item C:\Certs\ncrest.pfx         "$lib\ServerCertificate.cr\"
Copy-Item C:\Certs\ncrest-public.cer  "$lib\NCCertificate.cr\"
Copy-Item C:\Certs\etisalat-root.cer  "$lib\TrustedRootCertificate.cr\"
Get-ChildItem "$lib\ServerCertificate.cr", "$lib\NCCertificate.cr", "$lib\TrustedRootCertificate.cr" | Select-Object FullName
Remove-Item C:\Certs\ncrest.pfx      # the PFX now lives only in the library + vault
```

```powershell
# MGMT01 (VMM PowerShell)
Get-SCLibraryShare | Read-SCLibraryShare
Get-SCCustomResource | Where-Object SharePath -like "*\SDN\*" | Format-Table Name, SharePath
```

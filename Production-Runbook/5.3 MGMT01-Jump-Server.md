# 5.3 MGMT01 – management / jump server (HA VM on CSV)

> New step: the "Client VM" from `1. Prerequiste.md`. From here on, every GUI (Hyper-V Manager with copy/paste, Failover Cluster Manager, DNS, ADUC, VMM console, SSMS) runs on MGMT01.

## 1. Create it

```powershell
# HV01
. C:\ClusterStorage\CSV01\_Base\Build\New-InfraVM.ps1
$csv = "C:\ClusterStorage\CSV01"
New-InfraVM -Name MGMT01 -vCPU 4 -RAM 8GB -OSDiskSize 100GB -Path $csv -BaseVhdx "$csv\_Base\WS2025-DC-DE.vhdx" -Vlan 100
Set-VM -Name MGMT01 -AutomaticStartAction Nothing       # the cluster starts HA VMs, not the host
Add-ClusterVirtualMachineRole -VMName MGMT01
Start-ClusterGroup MGMT01

$local = Get-Credential -UserName "Administrator" -Message "Local admin password from 1.2"
$dom   = Get-Credential -UserName "ETISALAT\Administrator"
Wait-VMReady -Name MGMT01 -Credential $local
Expand-GuestC -Name MGMT01 -Credential $local

Invoke-Command -VMName MGMT01 -Credential $local -ScriptBlock {
    Rename-NetAdapter -Name (Get-NetAdapter | Select-Object -First 1).Name -NewName "Management"
    New-NetIPAddress -InterfaceAlias "Management" -IPAddress 10.10.100.40 -PrefixLength 24 -DefaultGateway 10.10.100.1
    Set-DnsClientServerAddress -InterfaceAlias "Management" -ServerAddresses 10.10.100.21, 10.10.100.22
    Add-Computer -DomainName etisalat.local -NewName MGMT01 -OUPath "OU=Management Servers,OU=Infrastructure,DC=etisalat,DC=local" -Credential $using:dom -Restart
}
Wait-VMReady -Name MGMT01 -Credential $dom
```

> The same pattern (`New-InfraVM` on CSV → `Add-ClusterVirtualMachineRole` → PowerShell Direct for IP + domain join → Windows Update) is used for SQL01 and VMM01.
> PowerShell Direct (`-VMName`) only works on the host that **currently runs** the VM (`Get-ClusterGroup MGMT01`).

## 2. Windows Update until nothing is left

```powershell
# HV01 (or the node that owns MGMT01) – update source: the "SRV - Update Source" GPO (2.1 §7) applies after the domain join. Check it:
Invoke-Command -VMName MGMT01 -Credential $dom -ScriptBlock {
    gpupdate /force | Out-Null
    netsh winhttp show proxy
    # only if a proxy is used and the GPO isn't (0.2 §1 #17 b):
    # netsh winhttp set proxy proxy-server="<proxy>:<port>" bypass-list="*.etisalat.local;10.10.*;<local>"
}
Update-GuestWindows -Name MGMT01 -Credential $dom
```

## 3. Tools (inside MGMT01, RDP as `ETISALAT\Administrator`)

```powershell
# MGMT01
Install-WindowsFeature RSAT-Hyper-V-Tools, RSAT-Clustering, RSAT-AD-Tools, RSAT-DNS-Server, RSAT-NetworkController, GPMC
```

- **Hyper-V Manager** → Connect to Server → HV01..HV04.
- **Failover Cluster Manager** → connect to `HVCL01`.
- Optional: **Windows Admin Center** (browser management of the Core hosts) and **SSMS** (SQL).
- VMM console: installed in 6.2.

## 4. Verify copy/paste

1. On MGMT01: Hyper-V Manager → HV01 → double-click **DC01** → in the connect dialog, **Show Options → Local Resources → Clipboard ✔ → Connect**.
2. Copy text on MGMT01 and paste it inside DC01. It must work.
3. If the dialog doesn't appear: **View → Enhanced Session** in the VM window, and check `Get-VMHost HV01 | Select EnableEnhancedSessionMode` = True.

## Gate 5.3

```powershell
# HV01 (or the node that owns MGMT01)
Get-ClusterGroup MGMT01 | Format-Table Name, OwnerNode, State      # Online
Test-GuestBaseline -Name MGMT01 -Credential $dom                    # Edition = ServerDatacenter, License = Licensed, Build = HostBuild
Move-ClusterVirtualMachineRole -Name MGMT01 -Node HV02 -MigrationType Live
```

- MGMT01 is domain joined and Online.
- Edition **Datacenter** (`EditionID = ServerDatacenter`), `License Status: Licensed` (AVMA). Same build as the hosts.
- The live migration to HV02 works with no ping loss.
- Copy/paste works into DC01.

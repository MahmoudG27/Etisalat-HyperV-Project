# 8.1 Network Controller certificate (Etisalat CA, CSR-based)

> The NC REST certificate secures VMM ↔ NC (northbound). VMM also uses it for NC ↔ hosts/MUX (southbound), so it needs **both** Server and Client Authentication.
> We generate the **CSR ourselves**: the private key never leaves us. Etisalat's CA only signs.
> Lab lesson **L4**: the NC setup script expects a **legacy CSP** key. A CNG/KSP key fails with "Path is null".

## 1. Certificate requirements

| Item | Value | Source |
|---|---|---|
| Subject | `CN=ncrest.etisalat.local` (the REST name; domain = 0.1 D2) | VMM "Set up an SDN network controller" |
| SAN | `dns=ncrest.etisalat.local` | – |
| EKU | Server Authentication `1.3.6.1.5.5.7.3.1` **and** Client Authentication `1.3.6.1.5.5.7.3.2` | "Manage certificates for SDN" |
| Key usage | Digital Signature + Key Encipherment | "Manage certificates for SDN" |
| Key | RSA 2048 (or more), **exportable**, machine key | – |
| Provider | **Microsoft Enhanced RSA and AES Cryptographic Provider** (ProviderType 24, legacy CSP) | Lab L4 |
| Hash | SHA256 | – |

## 2. Generate the CSR

```powershell
# MGMT01 (elevated)
New-Item -ItemType Directory -Path C:\Certs -Force | Out-Null
@'
[Version]
Signature = "$Windows NT$"

[NewRequest]
Subject = "CN=ncrest.etisalat.local"
KeySpec = 1
KeyLength = 2048
HashAlgorithm = sha256
Exportable = TRUE
MachineKeySet = TRUE
SMIME = FALSE
PrivateKeyArchive = FALSE
UserProtected = FALSE
UseExistingKeySet = FALSE
ProviderName = "Microsoft Enhanced RSA and AES Cryptographic Provider"
ProviderType = 24
RequestType = PKCS10
KeyUsage = 0xa0

[EnhancedKeyUsageExtension]
OID = 1.3.6.1.5.5.7.3.1
OID = 1.3.6.1.5.5.7.3.2

[Extensions]
2.5.29.17 = "{text}"
_continue_ = "dns=ncrest.etisalat.local&"
'@ | Set-Content C:\Certs\ncrest.inf -Encoding ascii

certreq -new C:\Certs\ncrest.inf C:\Certs\ncrest.csr
certutil -dump C:\Certs\ncrest.csr      # check Subject, SAN, EKU, key length before sending
```

`KeyUsage = 0xa0` = Digital Signature (0x80) + Key Encipherment (0x20). The pending private key stays in the MGMT01 machine store until `certreq -accept`.

## 3. What we send / what we get back

| We send to Etisalat | We get back |
|---|---|
| `ncrest.csr` | Signed certificate (`ncrest.cer`, Base-64) |
| Requested EKU: Server + Client Auth; template that keeps the SAN from the request | **Root** CA certificate (`etisalat-root.cer`) |
| Validity wanted (e.g. 2 years) | **Intermediate** CA certificate(s) (`etisalat-int.cer`) |
| Contact for renewal | CRL and AIA URLs (HTTP), validity dates, renewal contact |

## 4. Accept, export PFX and root .cer

```powershell
# MGMT01 (elevated) – put the returned files into C:\Certs first
certreq -accept C:\Certs\ncrest.cer

$cert = Get-ChildItem Cert:\LocalMachine\My | Where-Object Subject -eq "CN=ncrest.etisalat.local" | Sort-Object NotAfter -Descending | Select-Object -First 1
certutil -store my $cert.Thumbprint | Select-String "Provider"     # must show: Microsoft Enhanced RSA and AES Cryptographic Provider

$pfxPwd = Read-Host "PFX password (store in vault: NC-PFX)" -AsSecureString
Export-PfxCertificate -Cert $cert -FilePath C:\Certs\ncrest.pfx -Password $pfxPwd -ChainOption BuildChain
Export-Certificate    -Cert $cert -FilePath C:\Certs\ncrest-public.cer -Type CERT      # NC cert without private key (NCCertificate.cr)
# etisalat-root.cer as received = TrustedRootCertificate.cr
```

After the PFX is stored in the vault and copied to the library (8.3), **remove the private key from MGMT01**:

```powershell
# MGMT01
Remove-Item "Cert:\LocalMachine\My\$($cert.Thumbprint)" -DeleteKey
```

## 5. Trust Etisalat's CA on the whole fabric (GPO)

All computers that talk to NC (hosts, VMM01, MGMT01, NC/MUX/GW, later the Cluster2 hosts) must trust the chain.

1. On MGMT01 (GPMC): create GPO **`PKI - Etisalat CA Trust`**, link it at the **domain root** (all computers, including Domain Controllers).
2. Edit → *Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies*:
   - **Trusted Root Certification Authorities** → Import `etisalat-root.cer`
   - **Intermediate Certification Authorities** → Import `etisalat-int.cer`

> ⚠️ Microsoft: on the hosts and SLB/MUX nodes, the **Trusted Root** store must not contain any certificate whose "Issued to" differs from "Issued by". Otherwise NC southbound communication fails.
> **Intermediates go in the Intermediate store, never in Trusted Root.**

```powershell
# MGMT01 – apply and check on all hosts
Invoke-Command -ComputerName HV01,HV02,HV03,HV04,VMM01 -ScriptBlock {
    gpupdate /force | Out-Null
    [pscustomobject]@{
        Host        = $env:COMPUTERNAME
        RootPresent = [bool](Get-ChildItem Cert:\LocalMachine\Root | Where-Object Subject -like "*<Etisalat Root CN>*")
        NonSelfSignedInRoot = (Get-ChildItem Cert:\LocalMachine\Root | Where-Object { $_.Subject -ne $_.Issuer }).Count   # must be 0
    }
}
```

## 6. CRL reachability (the CRL lives on Etisalat's corporate network)

```powershell
# MGMT01, then on one host (HV01) – the chain, AIA and CRL must all be fetched
certutil -verify -urlfetch C:\Certs\ncrest-public.cer
```

```powershell
# MGMT01 → HV01
Copy-Item C:\Certs\ncrest-public.cer \\HV01\C$\Temp\ -Force
Invoke-Command -ComputerName HV01 -ScriptBlock { certutil -verify -urlfetch C:\Temp\ncrest-public.cer }
```

The output must end with `Leaf certificate revocation check passed` and `CertUtil: -verify command completed successfully`.
If the CRL isn't reachable, ask Etisalat to open HTTP to the CDP/AIA URLs from the Management VLAN (0.2 §6). Don't continue without a passing revocation check.

## 7. Variant: Etisalat prefers us to run the CA

Pointer only, not a full procedure: an **Enterprise Root CA** VM `CA01` in the fabric domain (AD CS, `Install-AdcsCertificationAuthority -CAType EnterpriseRootCa`), with a duplicated "Web Server" template that:
- has "Supply in the request",
- allows the private key to be exported,
- has Digital Signature + Key Encipherment,
- has Server + Client Authentication.

The same CSR (§2) is then submitted to `CA01`. Trust is automatic for domain members. Decide with Etisalat before 8.1. If chosen, write a separate CA runbook.

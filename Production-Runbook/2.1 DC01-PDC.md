# 2.1 DC01 – Primary Domain Controller (on HV01 local disk)

> Replaces `2. PDC.md`. Run on **HV01**.

## 1. Create the VM

```powershell
# HV01
. C:\Build\New-InfraVM.ps1
New-InfraVM -Name DC01 -vCPU 2 -RAM 8GB -OSDiskSize 100GB -Path "D:\VMs" -BaseVhdx "D:\VMs\_Base\WS2025-DC-DE.vhdx" -Vlan 100

# DC-specific settings
Set-VM -Name DC01 -CheckpointType Disabled -AutomaticStartDelay 0
# Time Synchronization integration service stays ENABLED (default). Only the VMICTimeProvider inside the guest is
# disabled (§5), so the DC still gets a corrected clock after a restore/saved state but syncs from NTP/domain otherwise.

Start-VM DC01
$local = Get-Credential -UserName "Administrator" -Message "Local admin password from 1.2"
Wait-VMReady -Name DC01 -Credential $local
Expand-GuestC -Name DC01 -Credential $local
```

## 2. IP, name

```powershell
# HV01
Invoke-Command -VMName DC01 -Credential $local -ScriptBlock {
    Rename-NetAdapter -Name (Get-NetAdapter | Select-Object -First 1).Name -NewName "Management"
    New-NetIPAddress -InterfaceAlias "Management" -IPAddress 10.10.100.21 -PrefixLength 24 -DefaultGateway 10.10.100.1
    Set-DnsClientServerAddress -InterfaceAlias "Management" -ServerAddresses 127.0.0.1
    Rename-Computer -NewName DC01 -Restart
}
Wait-VMReady -Name DC01 -Credential $local
```

## 3. Install AD DS and create the forest

```powershell
# HV01
$dsrm = Read-Host "DSRM (Safe Mode) password - store it in the password vault" -AsSecureString
Invoke-Command -VMName DC01 -Credential $local -ScriptBlock {
    Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
    Install-ADDSForest -DomainName "etisalat.local" -DomainNetbiosName "ETISALAT" `
        -InstallDns -SafeModeAdministratorPassword $using:dsrm -NoRebootOnCompletion:$false -Force
}
```

The VM reboots (5–10 min). From now on, log in with the **domain** account:

```powershell
# HV01
$dom = Get-Credential -UserName "ETISALAT\Administrator" -Message "Same password as the local admin"
Wait-VMReady -Name DC01 -Credential $dom
```

```powershell
    Resolve-DnsName microsoft.com
}
```

## 5. Time: the PDC is the time source for the whole domain

Approach used for **both** DCs (here and in 4.1): the Hyper-V **Time Synchronization integration service stays enabled**, and only the **VMICTimeProvider** inside the guest is disabled.
The DC never takes its time from the host during normal operation. But Hyper-V still corrects the clock after a restore or saved state.

```powershell
# HV01
Invoke-Command -VMName DC01 -Credential $dom -ScriptBlock {
    # Stop w32time from using the Hyper-V host as a time source
    Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\W32Time\TimeProviders\VMICTimeProvider" -Name Enabled -Value 0 -Type DWord

    # Replace with the corporate NTP servers if available
    w32tm /config /manualpeerlist:"0.pool.ntp.org,0x8 1.pool.ntp.org,0x8 time.windows.com,0x8" /syncfromflags:manual /reliable:yes /update
    Restart-Service w32time
    w32tm /resync /rediscover
    w32tm /query /status
    w32tm /query /source
}
```

`/query /source` must show the NTP server, **not** `Local CMOS Clock` or `VM IC Time Synchronization Provider`.
If it still shows `VM IC…` after a reboot, the registry change didn't take. Check the value, then restart `w32time`.

## 6. Sites, subnets, OU structure

```powershell
# HV01
Invoke-Command -VMName DC01 -Credential $dom -ScriptBlock {
    Get-ADReplicationSite -Identity "Default-First-Site-Name" | Rename-ADObject -NewName "Cairo-DC"
    "10.10.100.0/24","10.10.101.0/24","10.10.200.0/24" | ForEach-Object { New-ADReplicationSubnet -Name $_ -Site "Cairo-DC" }

    $root = (Get-ADDomain).DistinguishedName
    New-ADOrganizationalUnit -Name "Infrastructure" -Path $root
    $infra = "OU=Infrastructure,$root"
    "Hyper-V Hosts","Clusters","Management Servers","SDN","Service Accounts","Groups" |
        ForEach-Object { New-ADOrganizationalUnit -Name $_ -Path $infra }

    Get-ADOrganizationalUnit -Filter * -SearchBase $infra | Select-Object DistinguishedName
}
```

> If you rename the site, use the new name (`Cairo-DC`) in 4.1.

## 7. Update source for all servers (0.2 §1 #17)

Windows Update and MAK activation run as **SYSTEM** and use the **WinHTTP** proxy, not a user/browser proxy. Pick the case that matches Etisalat's answer.

**Default from here on: one GPO, `SRV - Update Source`**, linked to `OU=Infrastructure` (hosts, management VMs) **and** `OU=Domain Controllers` (DC01/DC02 aren't under `OU=Infrastructure`).

**Case (a) – WSUS:**

```powershell
# HV01
Invoke-Command -VMName DC01 -Credential $dom -ScriptBlock {
    $wsus = "http://<wsus-server>:8530"                       # from 0.2 §1 #17
    $root = (Get-ADDomain).DistinguishedName
    $gpo  = New-GPO -Name "SRV - Update Source" -Comment "WSUS for all infrastructure servers"
    $k    = "HKLM\Software\Policies\Microsoft\Windows\WindowsUpdate"
    Set-GPRegistryValue -Name $gpo.DisplayName -Key $k      -ValueName WUServer       -Type String -Value $wsus
    Set-GPRegistryValue -Name $gpo.DisplayName -Key $k      -ValueName WUStatusServer -Type String -Value $wsus
    Set-GPRegistryValue -Name $gpo.DisplayName -Key "$k\AU" -ValueName UseWUServer    -Type DWord  -Value 1
    Set-GPRegistryValue -Name $gpo.DisplayName -Key "$k\AU" -ValueName AUOptions      -Type DWord  -Value 2   # notify only: no automatic installs/reboots
    New-GPLink -Name $gpo.DisplayName -Target "OU=Infrastructure,$root"
    New-GPLink -Name $gpo.DisplayName -Target "OU=Domain Controllers,$root"
}
```

This is the GPO setting *"Specify intranet Microsoft update service location"*. `Update-GuestWindows` works the same against WSUS.

**Case (b) – HTTP proxy** (no authentication, or an auth exception for the management subnet: SYSTEM can't do user-based proxy auth):
Group Policy has no direct WinHTTP proxy setting, so the GPO runs `netsh` once as SYSTEM.
The GPO also sets **`AUOptions=2`** here: in **both** cases, no server installs or reboots on its own. Patching is done by `Update-GuestWindows` (VMs) and Cluster-Aware Updating (hosts, 6.6).

1. Create and link the GPO, with automatic installs disabled:

```powershell
# HV01
Invoke-Command -VMName DC01 -Credential $dom -ScriptBlock {
    $root = (Get-ADDomain).DistinguishedName
    $gpo  = New-GPO -Name "SRV - Update Source" -Comment "WinHTTP proxy + no automatic installs for all infrastructure servers"
    Set-GPRegistryValue -Name $gpo.DisplayName -Key "HKLM\Software\Policies\Microsoft\Windows\WindowsUpdate\AU" -ValueName AUOptions -Type DWord -Value 2   # notify only
    New-GPLink -Name $gpo.DisplayName -Target "OU=Infrastructure,$root"
    New-GPLink -Name $gpo.DisplayName -Target "OU=Domain Controllers,$root"
}
```

2. GPMC (on DC01 now or MGMT01 later) → edit `SRV - Update Source` → *Computer Configuration → Preferences → Control Panel Settings → Scheduled Tasks* → New → **Immediate Task (At least Windows 7)**:
   - Name `Set WinHTTP proxy`. User `NT AUTHORITY\SYSTEM`, "Run with highest privileges".
   - Action: Start a program `netsh`, arguments `winhttp set proxy proxy-server="<proxy>:<port>" bypass-list="*.etisalat.local;10.10.*;<local>"`.
   - Settings tab: "Apply once and do not reapply".

**Until the GPO applies** (DC01 right now, and any VM before its domain join), set the WinHTTP proxy directly inside the guest:

```powershell
# HV01 – only if a proxy is used (0.2 §1 #17)
Invoke-Command -VMName DC01 -Credential $dom -ScriptBlock {
    netsh winhttp set proxy proxy-server="<proxy>:<port>" bypass-list="*.etisalat.local;10.10.*;<local>"
    netsh winhttp show proxy
}
```


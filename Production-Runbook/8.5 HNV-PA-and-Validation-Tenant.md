## 2. Provider addresses and the PA path jumbo test (L9)

```powershell
# MGMT01
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock { Get-ProviderAddress } |
    Format-Table PSComputerName, ProviderAddress, VlanID, MacAddress      # typically 2 PAs per host (one per SET member)
```

The PA addresses live in a **separate TCP/IP compartment** on each host. Find the compartment number:

```powershell
# HV01
ipconfig /allcompartments /all | Select-String -Pattern "Compartment|IPv4 Address"
```

Ping from a PA on HV01 to a PA on HV02 **inside that compartment**, small and then full-size without fragmentation:

```powershell
# HV01 – <c> = compartment number, <pa-hv01> / <pa-hv02> from Get-ProviderAddress
ping -c <c> -S <pa-hv01> <pa-hv02>                     # basic reachability
ping -c <c> -S <pa-hv01> -f -l 1472 <pa-hv02>          # 1500-byte frame, must work (lab L9 failed here)
ping -c <c> -S <pa-hv01> -f -l 1600 <pa-hv02>          # > 1500: proves jumbo on the PA path
```

Microsoft's dedicated test (HNVDiagnostics module, on the hosts):

```powershell
# HV01
Test-LogicalNetworkSupportsJumboPacket -SourceHost HV01 -DestinationHost HV02
Test-LogicalNetworkSupportsJumboPacket -SourceHost HV03 -DestinationHost HV04
```

Microsoft's guidance: the PA path needs MTU ≥ **1674** end to end. If the test fails, a switch port, inter-switch link or router hop on the HNV-PA VLAN is still at 1500 (0.2 §3).

## 3. Temporary validation tenant ⚠️ delete at the end of this file

Two VM networks with the **same** CIDR prove both VXLAN forwarding and tenant isolation.

| Object | Tenant A | Tenant B |
|---|---|---|
| VM network | `VAL-TenantA` | `VAL-TenantB` |
| Logical network | `HNV-PA` | `HNV-PA` |
| Isolation | **Isolate using Hyper-V Network Virtualization** | same |
| VM subnet | `192.168.50.0/24` | `192.168.50.0/24` (same on purpose) |
| IP pool | `192.168.50.10–.50`, gateway `.1` (distributed router) | same |
| Test VMs | `VAL-A1` (on HV01), `VAL-A2` (on HV03) | `VAL-B1` (on HV02) |

VMs: VMM → **Create Virtual Machine** from `WS2025-DC-SDN.vhdx`:
- Gen2, 2 vCPU / 4 GB, workgroup, AVMA key.
- NIC on the tenant VM network, static IP from the pool.
- Pick the host manually: A1 and A2 must be on **different** hosts.

```powershell
# HV0x (host of each VAL VM) – allow ICMP + a TCP test port inside every validation VM
$c = Get-Credential "Administrator"
Invoke-Command -VMName VAL-A1 -Credential $c -ScriptBlock {
    New-NetFirewallRule -DisplayName "VAL ICMPv4" -Protocol ICMPv4 -Direction Inbound -Action Allow | Out-Null
    New-NetFirewallRule -DisplayName "VAL TCP 80" -Protocol TCP -LocalPort 80 -Direction Inbound -Action Allow | Out-Null
    Install-WindowsFeature Web-Server | Out-Null     # simple TCP/80 responder for 8.7 and ACL tests
    ipconfig
}
# repeat for VAL-A2 and VAL-B1
```

Tests:

```powershell
# inside VAL-A1 (VM console from MGMT01, or PowerShell Direct from its host)
ping 192.168.50.11                         # VAL-A2 on another host → must reply (VXLAN across hosts)
ping -f -l 1472 192.168.50.11              # full 1500-byte CA packet across hosts → must reply (L9)
Test-NetConnection 192.168.50.11 -Port 80  # TCP
ping 192.168.50.1                          # distributed router / gateway → replies
```

```powershell
# inside VAL-B1 (same IP space, other tenant)
ipconfig                                   # e.g. 192.168.50.10, possibly the SAME IP as VAL-A1
ping 192.168.50.11                         # must NOT reach VAL-A2 (isolation)
```

**Port ACL check (L18):** a port ACL with only Allow rules blocks nothing (default is Allow), and ICMP isn't stateful. When testing ACLs, always add an explicit **Deny-All** rule with the lowest priority, and test with **TCP** (`Test-NetConnection -Port 80`), not only ping.

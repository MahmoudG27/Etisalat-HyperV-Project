# 6.2 VMM01 – install System Center VMM 2025

> Replaces `6. SCVMM.md` / `Efada.md` (install part).

## 1. VM (on HV01): OS disk + 1 TB library disk

```powershell
. C:\ClusterStorage\CSV01\_Base\Build\New-InfraVM.ps1
$csv = "C:\ClusterStorage\CSV01"
New-InfraVM -Name VMM01 -vCPU 4 -RAM 16GB -OSDiskSize 150GB -Path $csv -BaseVhdx "$csv\_Base\WS2025-STD-DE.vhdx" -Vlan 100
Set-VM -Name VMM01 -AutomaticStartAction Nothing
New-VHD -Path "$csv\VMM01\Virtual Hard Disks\VMM01-Library.vhdx" -SizeBytes 1TB -Dynamic | Out-Null
Add-VMHardDiskDrive -VMName VMM01 -Path "$csv\VMM01\Virtual Hard Disks\VMM01-Library.vhdx"

Add-ClusterVirtualMachineRole -VMName VMM01
(Get-ClusterGroup VMM01).Priority = 2000      # Medium: after SQL01
Start-ClusterGroup VMM01

$local = Get-Credential -UserName "Administrator"
$dom   = Get-Credential -UserName "ETISALAT\Administrator"
Wait-VMReady -Name VMM01 -Credential $local
Expand-GuestC -Name VMM01 -Credential $local

Invoke-Command -VMName VMM01 -Credential $local -ScriptBlock {
    Rename-NetAdapter -Name (Get-NetAdapter | Select-Object -First 1).Name -NewName "Management"
    New-NetIPAddress -InterfaceAlias "Management" -IPAddress 10.10.100.32 -PrefixLength 24 -DefaultGateway 10.10.100.1
    Set-DnsClientServerAddress -InterfaceAlias "Management" -ServerAddresses 10.10.100.21, 10.10.100.22
    Add-Computer -DomainName etisalat.local -NewName VMM01 -OUPath "OU=Management Servers,OU=Infrastructure,DC=etisalat,DC=local" -Credential $using:dom -Restart
}
Wait-VMReady -Name VMM01 -Credential $dom

Invoke-Command -VMName VMM01 -Credential $dom -ScriptBlock {
    Get-Disk | Where-Object PartitionStyle -eq 'RAW' | Initialize-Disk -PartitionStyle GPT -PassThru |
        New-Partition -DriveLetter L -UseMaximumSize | Format-Volume -FileSystem NTFS -NewFileSystemLabel "VMMLibrary" -Confirm:$false
    New-Item -ItemType Directory -Path "L:\MSSCVMMLibrary" -Force | Out-Null

    # Local admins: the VMM service account and the VMM admin group
    Add-LocalGroupMember -Group Administrators -Member "ETISALAT\svc-vmm", "ETISALAT\GG-VMM-Admins"
}
```

## 2. Prerequisites (inside VMM01, RDP as `ETISALAT\Administrator`)

Download these on MGMT01 (internet), then copy them to `\\VMM01\C$\Install`:

| Item | Notes |
|---|---|
| **System Center 2025 VMM** (`SCVMM_2025.zip` / exe) | Evaluation Center or VLSC / Admin Center |
| **Windows ADK for Windows 11 / Server 2025** (`adksetup.exe`) | Only the **Deployment Tools** feature |
| **WinPE add-on** for the same ADK version (`adkwinpesetup.exe`) | Only **Windows Preinstallation Environment** |
| **Microsoft ODBC Driver 18 for SQL Server** (`msodbcsql.msi`) | VMM setup's prerequisite check tells you if it wants a different version |
| **SQL Server Command Line Utilities** (`MsSqlCmdLnUtils.msi`) | Matching the SQL version |

Optional: check the VMM zip hash (value from Microsoft's VMM 2025 install page):

```powershell
"223CE90811799223DA635EC66F81302ECBB3AB4842C37002AC29B23D556F5AAF" -eq (Get-FileHash C:\Install\SCVMM_2025.zip -Algorithm SHA256).Hash
```

Install the prerequisites silently:

```powershell
cd C:\Install
Start-Process .\adksetup.exe       -ArgumentList '/quiet /norestart /features OptionId.DeploymentTools' -Wait
Start-Process .\adkwinpesetup.exe  -ArgumentList '/quiet /norestart /features OptionId.WindowsPreinstallationEnvironment' -Wait
Start-Process msiexec -ArgumentList '/i msodbcsql.msi /qn IACCEPTMSODBCSQLLICENSETERMS=YES' -Wait
Start-Process msiexec -ArgumentList '/i MsSqlCmdLnUtils.msi /qn IACCEPTMSSQLCMDLNUTILSLICENSETERMS=YES' -Wait

Test-NetConnection SQL01 -Port 1433
Restart-Computer
```

## 3. Run VMM setup (GUI)

Extract the media, right-click `setup.exe` → **Run as administrator** → **Install**. Run it as `ETISALAT\Administrator`, which is `sysadmin` on SQL01 through `GG-SQL-Admins`.

| Page | Value |
|---|---|
| Features | ✔ **VMM management server** (the console is installed automatically) |
| Product registration | Name / Organization / **Product key** (empty = 180-day evaluation) |
| License | Accept |
| Diagnostic data / Microsoft Update | According to company policy (Update: **Off**, patch with Update Rollups manually) |
| Installation location | Default |
| Prerequisites | Must be all green. If something is missing, install it and click **Check prerequisites again** |
| **Database configuration** | Server name: **`SQL01`** · Port: *(empty)* · "Use the following credentials": unchecked (the current user is sysadmin) · Instance: **`MSSQLSERVER`** · **New database**: `VirtualManagerDB` |
| **Service account** | **Domain account** · `ETISALAT\svc-vmm` · its own password (from 4.2) |
| **Distributed Key Management** | ✔ **Store my keys in Active Directory** · `CN=VMMDKM,DC=etisalat,DC=local` (setup creates the container because you're Domain Admin). Required if you add a second VMM node later. Recommended always |
| Port configuration | Defaults (8100, 5985, 443, 8102, 8101, 8103) |
| **Library configuration** | Create a new library share · Share name `MSSCVMMLibrary` · Location **`L:\MSSCVMMLibrary`** |
| Install | 10–20 min |

Logs if anything fails: `C:\ProgramData\VMMLogs\`.

<details>

```cmd

```
</details>

## 4. After install

1. Install the **latest VMM 2025 Update Rollup** on VMM01 (server + console).
2. Install the **VMM console on MGMT01**: run the same media → Install → **VMM console** only (or `setup.exe /client /i /IACCEPTSCEULA`), then apply the same Update Rollup.
3. Give the admin group full rights in VMM (VMM PowerShell on VMM01):

```powershell
Import-Module VirtualMachineManager
Get-SCVMMServer -ComputerName VMM01.etisalat.local | Out-Null
Get-SCUserRole -Name "Administrator" | Set-SCUserRole -AddMember "ETISALAT\GG-VMM-Admins"
```

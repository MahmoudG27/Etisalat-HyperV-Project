## 5. Router side: handoff to Etisalat's network team (not executed by us)

| Item | Requirement |
|---|---|
| Neighbours | eBGP to **each MUX** (their HNV-PA addresses, from VMM / `ipconfig`), remote-as `<mux-asn>` |
| Topology | **Directly connected** on the HNV-PA VLAN, no multihop |
| ECMP | `maximum-paths 2` (or more): the same VIP /32 arrives from both MUX |
| Inbound filter | Accept **only /32s** inside `<private-vip-prefix>`, `<public-vip-prefix>`, `<gre-vip-prefix>`. Deny everything else |
| Outbound | Default route or nothing (as Etisalat prefers). MUX don't need full tables |
| Public VIPs | Redistribute/advertise the `<public-vip-prefix>` aggregate or the /32s toward the internet edge, per Etisalat policy |

Neutral example (adapt to the vendor syntax):

```
router bgp <router-asn>
  neighbor <MUX01-PA-IP> remote-as <mux-asn>
  neighbor <MUX02-PA-IP> remote-as <mux-asn>
  maximum-paths 2
  neighbor <MUX01-PA-IP> prefix-list SDN-VIP-IN in
  neighbor <MUX02-PA-IP> prefix-list SDN-VIP-IN in
prefix-list SDN-VIP-IN permit <private-vip-prefix> ge 32 le 32
prefix-list SDN-VIP-IN permit <public-vip-prefix>  ge 32 le 32
prefix-list SDN-VIP-IN permit <gre-vip-prefix>     ge 32 le 32
```

## 6. Temporary VIP test ⚠️ delete after the Gate

Uses `VAL-A1` / `VAL-A2` (8.5, IIS on TCP 80). Put the host name in each default page so you can see which backend answers:

```powershell
# HV0x (host of each VAL VM)
Invoke-Command -VMName VAL-A1 -Credential $c -ScriptBlock { "VAL-A1" | Set-Content C:\inetpub\wwwroot\iisstart.htm }
Invoke-Command -VMName VAL-A2 -Credential $c -ScriptBlock { "VAL-A2" | Set-Content C:\inetpub\wwwroot\iisstart.htm }
```

1. **Fabric → VIP Templates → Create VIP Template**: name `VAL-HTTP`, VIP port 80, backend port 80, Type **Specific** → Microsoft / **Microsoft Network Controller**, protocol **Custom TCP**, default persistence/LB, health monitor TCP 80.
2. Create the VIP with Microsoft's script (VMM 2025 "Load balance network traffic", external traffic):

```powershell
# MGMT01 (VMM PowerShell)
$lb   = Get-SCLoadBalancer | Where-Object { $_.Service.Name -like "NC" }
$net  = Get-SCVMNetwork -Name "PublicVIP"
$nics = "VAL-A1","VAL-A2" | ForEach-Object { (Get-SCVirtualMachine -Name $_).VirtualNetworkAdapters[0] }
$vipt = Get-SCLoadBalancerVIPTemplate -Name "VAL-HTTP"
New-SCLoadBalancerVIP -Name "VAL-VIP-80" -LoadBalancer $lb -IPAddress "<public-vip-prefix>.250" `
    -LoadBalancerVIPTemplate $vipt -FrontEndVMNetwork $net -BackEndVirtualNetworkAdapters $nics
```

3. Test from a machine **outside** the fabric (Etisalat network or internet, per their routing). New TCP connection each time (L12):

```powershell
# Test client outside the fabric
1..10 | ForEach-Object { (Invoke-WebRequest -Uri "http://<public-vip-prefix>.250" -UseBasicParsing -DisableKeepAlive).Content.Trim() }
```

Expect a mix of `VAL-A1` and `VAL-A2`. A single client reusing one connection always hits the same backend (L12): the MUX balances **per TCP connection**, not per HTTP request.

4. Stop `VAL-A1` and `VAL-A2` → the router **withdraws** the VIP /32 (L11: the MUX only advertises VIPs that have a healthy backend). Start them again → the VIP comes back.
5. Delete the VIP after the Gate: `Get-SCLoadBalancerVIP -Name "VAL-VIP-80" | Remove-SCLoadBalancerVIP`. Keep the VIP template, or delete it.

### SLB troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| VIP not advertised in BGP (**L11**) | No running/healthy backend behind it | Start a backend VM, check the health probe port |
| Always the same backend (**L12**) | Keep-alive reuses one TCP connection | Test with new connections (`-DisableKeepAlive`, several clients) |
| BGP session not Established | Wrong peer IP/ASN, not directly connected, filtered TCP 179 | Compare §4 with the router config. Check the PA VLAN path |
| Deployment error 22655 (**L3**) | Guest Agent missing | 8.4 §4 |
| Compatibility error (**L2**) | Template OS compatibility | §2 |

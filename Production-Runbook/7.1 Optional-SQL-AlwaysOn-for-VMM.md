# 7.1 (Optional) SQL01 + SQL02 Always On Availability Group for the VMM database

> Based on Microsoft "Deploy SQL Server for VMM high availability" (VMM 2025).
> Can be done any time after 6.2. Downtime: the **VMM service only**, ~15–30 min. Hosts, VMs, NC and tenants keep running.

| New object | Value |
|---|---|
| SQL02 | 10.10.100.33 (same build as SQL01: same disks, letters, paths, SQL version and CU) |
| Guest cluster `SQLCL01` | 10.10.100.34 (no shared storage) |
| AG `AG-VMM` | Synchronous commit, automatic failover |
| Listener `SQLAG-VMM` | 10.10.100.35, port 1433 |
| SQL service account | `ETISALAT\svc-sql` (domain account, needed for AG endpoints + Kerberos) |

**SQL Standard** supports a **Basic AG** (2 replicas, 1 database per AG, no readable secondary). That's enough for VMM (one database). Enterprise isn't required.

## 1. Build SQL02

Repeat **6.1** with `SQL02` / `10.10.100.33`. Use **exactly** the same drive letters and folders (`D:\SQL\Data`, `E:\SQL\Log`) and the same SQL CU.

Keep SQL01 and SQL02 on **different hosts** (host-cluster anti-affinity):

```powershell
# On HV01
foreach ($g in "SQL01","SQL02") {
    $ac = New-Object System.Collections.Specialized.StringCollection; [void]$ac.Add("SQL-AG")
    (Get-ClusterGroup $g).AntiAffinityClassNames = $ac
}
```

## 2. Domain service account + SPNs (on DC01)

```powershell
$pw = Read-Host "svc-sql password" -AsSecureString
New-ADUser -Name svc-sql -SamAccountName svc-sql -Path "OU=Service Accounts,OU=Infrastructure,DC=etisalat,DC=local" `
    -AccountPassword $pw -Enabled $true -PasswordNeverExpires $true -CannotChangePassword $true

setspn -S MSSQLSvc/SQL01.etisalat.local:1433     ETISALAT\svc-sql
setspn -S MSSQLSvc/SQL01.etisalat.local          ETISALAT\svc-sql
setspn -S MSSQLSvc/SQL02.etisalat.local:1433     ETISALAT\svc-sql
setspn -S MSSQLSvc/SQL02.etisalat.local          ETISALAT\svc-sql
setspn -S MSSQLSvc/SQLAG-VMM.etisalat.local:1433 ETISALAT\svc-sql
setspn -S MSSQLSvc/SQLAG-VMM.etisalat.local      ETISALAT\svc-sql
```

On SQL01 and SQL02: **SQL Server Configuration Manager → SQL Server (MSSQLSERVER) → Log On → `ETISALAT\svc-sql`**. Do the same for SQL Server Agent, then restart.
(Always use Configuration Manager, not services.msc, so permissions are applied correctly.)
Remove the old SPNs that SQL registered on the computer accounts: `setspn -D MSSQLSvc/SQL01.etisalat.local:1433 SQL01` (and the same for SQL02).

## 3. Guest failover cluster for the SQL VMs

```powershell
# On SQL01 and SQL02
Install-WindowsFeature Failover-Clustering -IncludeManagementTools -Restart
New-NetFirewallRule -DisplayName "SQL AG endpoint 5022" -Direction Inbound -Protocol TCP -LocalPort 5022 -Action Allow -Profile Domain
```

```powershell
# On SQL01
Test-Cluster -Node SQL01, SQL02
New-Cluster -Name "CN=SQLCL01,OU=Clusters,OU=Infrastructure,DC=etisalat,DC=local" -Node SQL01, SQL02 -StaticAddress 10.10.100.34 -NoStorage

# File share witness (on MGMT01 – any server outside this cluster)
Invoke-Command -ComputerName MGMT01 -ScriptBlock {
    New-Item C:\Witness\SQLCL01 -ItemType Directory -Force
    New-SmbShare -Name "Witness-SQLCL01$" -Path C:\Witness\SQLCL01 -FullAccess "ETISALAT\SQLCL01$", "ETISALAT\Domain Admins"
    icacls C:\Witness\SQLCL01 /grant "ETISALAT\SQLCL01$:(OI)(CI)F"
}
Set-ClusterQuorum -Cluster SQLCL01 -FileShareWitness "\\MGMT01\Witness-SQLCL01$"
```

## 4. Enable Always On (both nodes)

**SQL Server Configuration Manager → SQL Server (MSSQLSERVER) → Properties → Always On Availability Groups → ✔ Enable → restart the service.**
Or from MGMT01:

```powershell
Install-Module SqlServer -Scope AllUsers
Enable-SqlAlwaysOn -ServerInstance SQL01 -Force
Enable-SqlAlwaysOn -ServerInstance SQL02 -Force
```

## 5. Move VirtualManagerDB into the AG (Microsoft's order)

1. **Stop VMM:** on VMM01 `Stop-Service SCVMMService` (on an HA VMM: stop the VMM role in Failover Cluster Manager).
2. SSMS → SQL01 → `VirtualManagerDB` → Properties → Options → **Recovery model = Full**.
3. Take a **full backup** of `VirtualManagerDB`.
4. SSMS → **Always On High Availability → New Availability Group Wizard**:
   - Name `AG-VMM`, **Basic availability group** (Standard edition)
   - Database `VirtualManagerDB`
   - Replicas SQL01 + SQL02: **Synchronous commit**, **Automatic failover**, endpoint port 5022
   - **Listener:** `SQLAG-VMM`, port **1433**, static IP **10.10.100.35/24**
   - Data synchronization: **Automatic seeding** (or Full with a shared backup folder)
   - Validation → Finish
5. **Login on SQL02:** VMM's login exists only on SQL01. On **SQL02**:

```sql
CREATE LOGIN [ETISALAT\svc-vmm] FROM WINDOWS;
-- the database user already comes with the AG; after a failover verify it's mapped as db_owner:
-- USE VirtualManagerDB; ALTER ROLE db_owner ADD MEMBER [ETISALAT\svc-vmm];
```

6. **Point VMM to the listener** (on VMM01, back up the key first):

```powershell
$k = "HKLM:\SOFTWARE\Microsoft\Microsoft System Center Virtual Machine Manager Server\Settings\Sql"
reg export "HKLM\SOFTWARE\Microsoft\Microsoft System Center Virtual Machine Manager Server\Settings\Sql" C:\Install\vmm-sql-backup.reg
Get-ItemProperty $k | Select-Object ConnectionString, MachineName, InstanceName, MachineFQDN

$cs = (Get-ItemProperty $k).ConnectionString
Set-ItemProperty $k -Name ConnectionString -Value ($cs -replace 'SQL01(\.etisalat\.local)?', 'SQLAG-VMM')
Set-ItemProperty $k -Name MachineName      -Value 'SQLAG-VMM'
Set-ItemProperty $k -Name InstanceName     -Value 'SQLAG-VMM'
Set-ItemProperty $k -Name MachineFQDN      -Value 'SQLAG-VMM.etisalat.local'
Get-ItemProperty $k | Select-Object ConnectionString, MachineName, InstanceName, MachineFQDN

Start-Service SCVMMService
```

## 6. Failover test (Microsoft's validation)

1. SSMS on **SQL02** → `AG-VMM` → **Failover** → SQL02 becomes primary.
2. On VMM01: `Restart-Service SCVMMService` → open the VMM console. Hosts are visible and jobs run.
3. Fail back to SQL01, restart SCVMMService, check again.

---

## Gate 7.1

- `AG-VMM` dashboard is **green**, both replicas **Synchronized**.
- `Test-NetConnection SQLAG-VMM -Port 1433` from VMM01 succeeds.
- `setspn -Q MSSQLSvc/SQLAG-VMM.etisalat.local:1433` returns `svc-sql`.
- The VMM console works with SQL01 as primary **and** with SQL02 as primary.

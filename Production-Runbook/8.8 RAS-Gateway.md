## 1. Redundancy model and placement

| Item | Decision | Why |
|---|---|---|
| Model | **M+N = 1+1** in one gateway pool: **GW01 active, GW02 standby**. VMM field **"Nodes reserved for failures" = 1** | Microsoft: each pool is M+N redundant, N ≤ M. NC detects a failed gateway (VM, host or service) and moves its connections and VIPs to a standby |
| Scale later | Add **GW03 → 2+1** (2 active, 1 standby) when **either** the 0.2 §6 answers (IPsec/L3 usage and throughput per customer) **or** pilot measurements show that the IPsec/L3 load, or the number of gateway-connected tenants, is too much for **one** active GW. Benchmarks: §5 limits (50 VM networks, IPsec = 3/20 of capacity) and measured throughput | Pools scale without disruption (Microsoft) |
| Placement | GW01 and GW02 on **different hosts**, on CSV01 | Host failure must not take both |
| Live migration | **Not used for GW VMs**: deploy them **without** HA in the template (not clustered roles), `AutomaticStartAction Start`, `AutomaticStopAction ShutDown` | Microsoft: "RAS gateway VMs can't be migrated live without losing tenant connections". During host updates the GW stays on its host and NC fails over to the standby. Design choice: **to be verified in the pilot** |

**CAU (6.6) with gateways:**
- When CAU drains a host, a non-clustered GW on it shuts down with the host.
- NC fails its connections over to the standby GW once.
- After the reboot the GW comes back as standby.

Microsoft recommends updating the hosts with the **standby** gateway first. Check which GW is active before a CAU run (§7c) and order the nodes if possible.

If the pilot shows that a non-HA GW on a CAU-drained host causes **more than one failover** or a **long outage**, re-evaluate HA for the GW VMs.

## 5. Microsoft limits worth knowing

| Item | Value | Source |
|---|---|---|
| `MaxVMNetworksSupported` | **50** per NC-managed gateway (default) | VMM 2025 "Set up an SDN RAS Gateway" |
| `MaxVPNConnectionsPerVMNetwork` | **10** | same |
| `MaxVMSubnetsSupported` | **550** (includes one internal routing subnet per VM network) | same |
| `MaxVPNConnectionsSupported` | **250** | same |
| Override | Append e.g. `;MaxVMNetworksSupported=100` to the NC connection string (may affect NC performance) | same |
| IPsec throughput | **3/20** of the gateway capacity (1000 Mbps capacity = 150 Mbps IPsec), inbound + outbound combined | same |
| GRE / L3 throughput | **1/5** / **1/2** of the gateway capacity | same |
| L3 connection bandwidth limit | Can't be limited | VMM "Route traffic across networks" |

With 25 customers today, 50 VM networks per gateway leaves headroom. Absolute throughput per GW VM on this hardware: **to be measured** in the pilot.

## 6. Asymmetric routing check (L13) and capture tips (L14)

L13 happened because a customer office IP fell inside the gateway's management subnet, so replies left through the management NIC.
- **Rule:** the Management network (and its routing) must never contain customer office or internet addresses.
- **Check on each GW:** the route to a test office public IP must leave through the PA/frontend NIC, not Management.

```powershell
# HV0x (host of each GW) – credentials via -ArgumentList if nested (L20)
$c = Get-Credential "Administrator"
Invoke-Command -VMName GW01 -Credential $c -ArgumentList "<test-office-public-ip>" -ScriptBlock {
    param($ip)
    Find-NetRoute -RemoteIPAddress $ip | Select-Object InterfaceAlias, IPAddress, NextHop -Unique
    Get-NetIPConfiguration | Format-Table InterfaceAlias, IPv4Address, IPv4DefaultGateway
}
```

`InterfaceAlias` must be the frontend/PA NIC, **not** the Management NIC.

**pktmon (L14):**
- Filter on ESP, then search the output for `ESP\(spi` (a filter on "ESP" also matches "NONESP").
- Never pipe through `Select -First`: it hides the lines you need.

```powershell
# inside GW01
pktmon filter add -t ESP ; pktmon start --etw -c ; <reproduce> ; pktmon stop
pktmon format PktMon.etl -o C:\Temp\pkt.txt
Select-String -Path C:\Temp\pkt.txt -Pattern 'ESP\(spi'      # full output, no truncation
```

## 7. Temporary validation of the connection types ⚠️ delete after the Gate

On `VAL-TenantA` (VMs `VAL-A1`, `VAL-A2`):

**a) IPsec site-to-site** (only if Etisalat provides a test peer, otherwise mark "validated at the first customer pilot"):
1. VM network `VAL-TenantA` → Properties → **Connectivity** → ✔ Connect to another network through a VPN tunnel → gateway device `NC`.
2. **VPN Connections → Add → Add IPSec Tunnel**:
   - Routing subnet `10.254.254.0/29` (any subnet not used elsewhere).
   - Remote endpoint `<test-peer-public-ip>`.
   - PSK via a Run As account (vault).
   - Routes: the peer's test subnet.
3. Fill **every tab**, then **View Script** before OK (L17). Save the script and use the IDs from it in later queries (L19).
4. On the peer, the destination is the VM network endpoint IP shown in VMM (the public IPv4 from §4).
5. Ping the peer's test host from `VAL-A1`.

**b) L3 connection** on the test VLAN from Etisalat (0.2 §6):
1. Logical network `VAL-L3-NextHop`: Connected, ✔ VM network with same name, ✔ Managed by NC, site VLAN `<test-vlan>`, subnet `<test-/29>`.
2. Pool from `.2` (L15). Etisalat's peer (e.g. FortiGate) must **not** use the first usable IP.
3. Add the VLAN to the host trunk/`UPP-Converged` site list.
4. `VAL-TenantA` → Connectivity → **Add Layer 3 tunnel**:
   - Routing subnet.
   - Next-hop VM network `VAL-L3-NextHop`.
   - Local IP `<test-/29 .3>/29`.
   - Peer IP `<test-/29 .2 or Etisalat's choice>`.
   - Static route to Etisalat's test subnet.
5. Etisalat adds the return route for `192.168.50.0/24` via our local IP.
6. Ping both ways.

**After any change** to a connection on a VM network, re-test **all** its connections, and reconnect if a tunnel shows Connected but passes no traffic (stale SAs, **L16**).

**c) Failover test:**

```powershell
# MGMT01 – which gateway is active?
$uri  = "https://ncrest.etisalat.local"
$cred = Get-Credential "ETISALAT\svc-sdn"          # member of DL-NC-Users
Get-NetworkControllerGateway -ConnectionUri $uri -Credential $cred |
    ForEach-Object { "$($_.ResourceId)  State=$($_.Properties.State)  Type=$($_.Properties.Type)" }
```

Stop the **active** GW VM (from its host: `Stop-VM GWxx`). Within minutes the tunnels from (a)/(b) must come back on the other GW (NC failover). Start the GW again: it rejoins as standby.

### Gateway troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Tunnel Connected, no traffic (**L13**) | Asymmetric routing via the management NIC | §6 `Find-NetRoute`. Keep office/internet IPs out of the management network |
| Can't find ESP packets (**L14**) | Filter matched NONESP / output truncated | Search `ESP\(spi`, full output |
| Pool rejected / peer conflict (**L15**) | First IP reserved on NC subnets | Pools from `.2`. The peer never uses the first usable IP |
| Connected but broken after another connection was added (**L16**) | Stale IPsec SAs | Re-test all connections, reconnect |
| Gateway created without NAT connection (**L17**) | OK pressed early | Fill every tab, **View Script**, then OK |
| `Get-SCNATConnection -VMNetworkGateway` returns nothing (**L19**) | Query method | Query by the ID shown in View Script |
| Error 22655 (**L3**) | Guest Agent missing | 8.4 §4 |

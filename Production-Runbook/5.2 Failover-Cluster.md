# 5.2 Failover Cluster HVCL01 (witness, CSV, networks, live migration)

> Replaces the second half of `5. Failover-Cluster.md`. Everything here runs on **HV01 only**, as `ETISALAT\Administrator`, unless stated otherwise.

## 1. Prepare the LUNs (HV01 only)

```powershell
Get-Disk | Where-Object BusType -eq iSCSI | Format-Table Number, FriendlyName, @{n='SizeGB';e={[math]::Round($_.Size/1GB)}}, IsOffline
```

Take the disk numbers from the output (the example uses 2 = 5 GB witness, 3 = big CSV):

```powershell
$WitnessDisk = 2
$CsvDisk     = 3

Set-Disk -Number $WitnessDisk -IsOffline $false
Initialize-Disk -Number $WitnessDisk -PartitionStyle GPT
New-Partition -DiskNumber $WitnessDisk -UseMaximumSize | Format-Volume -FileSystem NTFS -NewFileSystemLabel "Witness" -Confirm:$false

Set-Disk -Number $CsvDisk -IsOffline $false
Initialize-Disk -Number $CsvDisk -PartitionStyle GPT
New-Partition -DiskNumber $CsvDisk -UseMaximumSize | Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel "CSV01" -Confirm:$false
```

- **NTFS, not ReFS**: on a SAN (non-S2D), a ReFS CSV always runs in file-system-redirected mode (all I/O goes through the coordinator node). NTFS gives direct I/O from every node.
- No drive letters: the cluster doesn't need them.
- ⚠️ **Do not online these disks on HV02–HV04.** Mounting the same NTFS volume on several non-clustered servers corrupts it. The cluster takes ownership in step 3.

## 2. Validate

```powershell
Test-Cluster -Node HV01,HV02,HV03,HV04 -Include "Inventory","Network","System Configuration","Storage","Hyper-V Configuration"
```

Open the HTML report (path shown at the end, under `C:\Windows\Cluster\Reports\`). Copy it to your PC to read it.
- **Must be clean:** Storage (SCSI-3 persistent reservation, disk failover), Hyper-V configuration, same updates on all nodes.
- **Acceptable warnings:** "single NIC on iSCSI network" (expected: one NIC per subnet), unsigned drivers from the vendor (check), DC01/DC02 not clustered.

## 3. Create the cluster

```powershell
New-Cluster -Name "CN=HVCL01,OU=Clusters,OU=Infrastructure,DC=etisalat,DC=local" `
    -Node HV01,HV02,HV03,HV04 -StaticAddress 10.10.100.20 -NoStorage `
    -IgnoreNetwork 10.10.101.0/24, 10.10.110.0/24, 10.10.111.0/24
```

- The CNO is created inside `OU=Clusters`.
- `-NoStorage` means disks are added deliberately below, not automatically.
- `-IgnoreNetwork` keeps the cluster IP on Management only.

## 4. Storage: witness + CSV

```powershell
Get-ClusterAvailableDisk | Format-Table Name, Number, @{n='SizeGB';e={[math]::Round($_.Size/1GB)}}

$w = Get-ClusterAvailableDisk | Where-Object Number -eq $WitnessDisk | Add-ClusterDisk
$w.Name = "Witness"
$c = Get-ClusterAvailableDisk | Where-Object Number -eq $CsvDisk | Add-ClusterDisk
$c.Name = "CSV01"

Set-ClusterQuorum -DiskWitness "Witness"
Add-ClusterSharedVolume -Name "CSV01"

# Friendly CSV path: C:\ClusterStorage\CSV01 instead of Volume1
Rename-Item -Path "C:\ClusterStorage\Volume1" -NewName "CSV01"
Get-ClusterSharedVolume | Format-List Name, State, @{n='Path';e={$_.SharedVolumeInfo.FriendlyVolumeName}}
```

## 5. Cluster networks

```powershell
Get-ClusterNetwork | Format-Table Name, Address, Role

(Get-ClusterNetwork | Where-Object Address -eq "10.10.100.0").Name = "Management"
(Get-ClusterNetwork | Where-Object Address -eq "10.10.101.0").Name = "LiveMigration"
(Get-ClusterNetwork | Where-Object Address -eq "10.10.110.0").Name = "iSCSI-A"
(Get-ClusterNetwork | Where-Object Address -eq "10.10.111.0").Name = "iSCSI-B"

(Get-ClusterNetwork "Management").Role    = "ClusterAndClient"
(Get-ClusterNetwork "LiveMigration").Role = "Cluster"
(Get-ClusterNetwork "iSCSI-A").Role       = "None"     # never use storage NICs for cluster traffic
(Get-ClusterNetwork "iSCSI-B").Role       = "None"

Get-ClusterNetwork | Format-Table Name, Address, Role
```

## 6. Live migration network + settings

```powershell
# Exclude the iSCSI networks from live migration; prefer LiveMigration, fall back to Management
$exclude = (Get-ClusterNetwork | Where-Object Name -in "iSCSI-A","iSCSI-B").ID -join ";"
$order   = ((Get-ClusterNetwork "LiveMigration").ID, (Get-ClusterNetwork "Management").ID) -join ";"
Get-ClusterResourceType -Name "Virtual Machine" | Set-ClusterParameter -Name MigrationExcludeNetworks -Value $exclude
Get-ClusterResourceType -Name "Virtual Machine" | Set-ClusterParameter -Name MigrationNetworkOrder   -Value $order

# Per-host Hyper-V settings + default VM path on the CSV
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock {
    Set-VMHost -VirtualMachineMigrationPerformanceOption Compression -MaximumVirtualMachineMigrations 2 -MaximumStorageMigrations 2
    Set-VMHost -VirtualHardDiskPath "C:\ClusterStorage\CSV01" -VirtualMachinePath "C:\ClusterStorage\CSV01"
}
```

## 7. Move the golden image to the CSV (visible from every host)

```powershell
New-Item -ItemType Directory -Path "C:\ClusterStorage\CSV01\_Base" -Force | Out-Null
Copy-Item "D:\VMs\_Base\WS2025-DC-DE.vhdx" "C:\ClusterStorage\CSV01\_Base\"
Copy-Item "C:\Build" "C:\ClusterStorage\CSV01\_Base\Build" -Recurse -Force
```

## 8. Remember: DC01 / DC02 are NOT cluster roles

They stay on the local `D:` of HV01/HV02 and start with the host. Never run `Add-ClusterVirtualMachineRole` on them. This way AD is up even when the cluster or SAN isn't.

## 9. Antivirus (only if Etisalat enforces an AV product)

In addition to the Hyper-V host exclusions (1.1 §11), apply Microsoft's cluster exclusions. See **"Virus scanning recommendations for Enterprise computers that are running currently supported versions of Windows"**, Failover Clustering section, and **"Antivirus exclusions for VMM and managed hosts"**. Well-known items:
- `C:\ClusterStorage` (all CSVs) – exclude it from scanning, *and* don't scan CSVs from the network side.
- `%SystemRoot%\Cluster`
- The witness disk.

## Gate 5.2

```powershell
# HV01
Get-Cluster | Format-List Name, Domain
Get-ClusterNode | Format-Table Name, State                          # 4 x Up
Get-ClusterQuorum | Format-List QuorumResource                     # Witness
Get-ClusterSharedVolume | Format-Table Name, State, OwnerNode       # CSV01 Online
Get-ClusterNetwork | Format-Table Name, Role, State                 # all Up
Test-Cluster -Node HV01,HV02,HV03,HV04 -Include "Storage" -Disk "CSV01"   # optional final storage test (takes CSV offline briefly)
```

Failover test: `Move-ClusterSharedVolume CSV01 -Node HV03`, then `Suspend-ClusterNode HV02 -Drain` and `Resume-ClusterNode HV02 -Failback Immediate`.

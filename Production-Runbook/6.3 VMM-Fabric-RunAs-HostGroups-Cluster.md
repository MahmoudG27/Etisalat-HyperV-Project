# 6.3 VMM fabric: Run As accounts, host groups, add the cluster, library

> Run on **MGMT01**: VMM console, or **VMM PowerShell** (`Import-Module VirtualMachineManager`).
> Tip: every VMM wizard has a **View Script** button. Save the script it shows; that's your exact, reproducible change log.

```powershell
Import-Module VirtualMachineManager
Get-SCVMMServer -ComputerName VMM01.etisalat.local | Out-Null
```

## 1. Run As accounts

| Name | Account | Used for | "Validate domain credentials" |
|---|---|---|---|
| `RA-HostAdmin` | `ETISALAT\svc-vmm-ras` | Add/manage Hyper-V hosts + cluster | ✔ |
| `RA-SDN` | `ETISALAT\svc-sdn` | NC `MgmtDomainAccount` + network service connection | ✔ |
| `RA-NC-LocalAdmin` | `Administrator` (local) | Local admin inside NC VMs | ✘ (uncheck: it's a local account) |
| `RA-DomainJoin` | `ETISALAT\svc-sdn` | Domain join in VM templates (optional, can reuse RA-SDN) | ✔ |

Console: **Settings → Security → Run As Accounts → Create Run As Account**.
PowerShell:

```powershell
New-SCRunAsAccount -Name "RA-HostAdmin"     -Credential (Get-Credential "ETISALAT\svc-vmm-ras")
New-SCRunAsAccount -Name "RA-SDN"           -Credential (Get-Credential "ETISALAT\svc-sdn")
New-SCRunAsAccount -Name "RA-NC-LocalAdmin" -Credential (Get-Credential "Administrator") -NoValidation
Get-SCRunAsAccount | Format-Table Name, UserName, Domain
```

> Microsoft's note for `RA-NC-LocalAdmin`: the user name must be `Administrator` (local). Choose a strong password. It becomes the local admin password of NC01–NC03.

## 2. Host groups

SDN needs a **dedicated host group** for the hosts that NC will manage. Later, the 12 old servers (cluster HVCL02) go under the same parent so the same NC manages both clusters.

```
All Hosts
└── SDN
    ├── HVCL01      (4 new hosts – management + customers)
    └── HVCL02      (12 old hosts – later)
```

```powershell
$sdn = New-SCVMHostGroup -Name "SDN"
New-SCVMHostGroup -Name "HVCL01" -ParentHostGroup $sdn
New-SCVMHostGroup -Name "HVCL02" -ParentHostGroup $sdn
```

## 3. Add the cluster HVCL01

Console: **Fabric → Servers → All Hosts → SDN → HVCL01** → right-click → **Add Hyper-V Hosts and Clusters** → "Windows Server computers in a trusted AD domain" → Run As `RA-HostAdmin` → search `HVCL01` → select the **cluster** (all 4 nodes come with it) → host group `SDN\HVCL01` → **don't** tick "Reassociate…" → Finish.

PowerShell:

```powershell
$hg  = Get-SCVMHostGroup -Name "HVCL01"
$ras = Get-SCRunAsAccount -Name "RA-HostAdmin"
Add-SCVMHostCluster -Name "HVCL01.etisalat.local" -VMHostGroup $hg -Credential $ras
```

The job installs the VMM agent on HV01–HV04 (5–10 min).

```powershell
Get-SCVMHostCluster | Format-Table Name, ClusterReserve
Get-SCVMHost | Format-Table Name, OverallState, CommunicationState, HostCluster, VirtualizationPlatform
```

Recommended cluster settings:
- **Cluster reserve = 1** (`Set-SCVMHostCluster -VMHostCluster (Get-SCVMHostCluster HVCL01) -ClusterReserve 1`). VMM then warns before you place more VMs than 3 hosts can carry.
- Host **Properties → Host Reserves**: keep at least 4 GB RAM / 10 % CPU for the parent partition.

## 4. Library

The library share `\\VMM01\MSSCVMMLibrary` is added automatically. Create the folder layout:

```powershell
"ISO","VHDs","SDN","Scripts" | ForEach-Object { New-Item -ItemType Directory -Path "\\VMM01\MSSCVMMLibrary\$_" -Force }
Get-SCLibraryShare | Read-SCLibraryShare        # refresh
```

Copy `WindowsServer2025.iso` into `\ISO`. NC templates and VHDX go into `\SDN` and `\VHDs` in 6.5.

## 5. Infrastructure VMs now visible in VMM

DC01, DC02, SQL01, VMM01 and MGMT01 appear under **VMs and Services** automatically. Don't delete or recreate them. Their network settings are attached to VMM objects in 6.4 §7.

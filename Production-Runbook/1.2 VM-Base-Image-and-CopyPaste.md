# 1.2 VM base image, `New-InfraVM` helper, and Copy/Paste into VMs

> New step (missing in the original). Run on **HV01**.
>
> **Why:** the hosts are Server Core, so there's no `vmconnect` and no GUI to click through a Windows installer inside DC01.
> Instead, Windows is applied **directly into a VHDX** from the ISO (the same method Microsoft uses for deployments), with an answer file.
> Each VM then boots straight to a ready OS, and the rest is configured with **PowerShell Direct** (`Invoke-Command -VMName`), which needs no network.

## 0. Prerequisite: licensed media

The Windows Server 2025, SQL Server 2022 and VMM 2025 media **must** be the licensed (non-evaluation) media from Etisalat's licensing program (0.2 §9).
**No Evaluation Center downloads in production.** Evaluation images that can't activate online shut themselves down every hour, and the management VMs sit on an isolated management network.

## 1. Copy the ISOs to the host

From your laptop (same network, before the domain exists):

```powershell
# Admin laptop
net use \\10.10.100.11\C$ /user:HV01\Administrator
New-Item -ItemType Directory -Path \\10.10.100.11\C$\ISO -Force
Copy-Item "C:\Path\To\WindowsServer2025.iso" \\10.10.100.11\C$\ISO\WindowsServer2025.iso
```

(Or mount the ISO as virtual media in iLO/iDRAC and copy it from there.)

## 2. Build the golden VHDX (one time)

```powershell
# HV01
$Iso      = "C:\ISO\WindowsServer2025.iso"           # licensed media, not Evaluation
$BaseDir  = "D:\VMs\_Base"
$Edition  = "*Datacenter (Desktop Experience)*"   # ONE golden image for every management VM (DC/SQL/VMM/MGMT, later NC/MUX/GW)
$BaseVhdx = "$BaseDir\WS2025-DC-DE.vhdx"
$LocalAdminPassword = "CHANGE-ME-Local!Adm1n"     # temporary local admin password inside new VMs
$ProductKey = "YQB4H-NKHHJ-Q6K4R-4VMY6-VCH67"     # AVMA key, Windows Server 2025 Datacenter (Microsoft "Automatic Virtual Machine Activation in Windows Server" page)
# Fallback ONLY if Etisalat confirms a KMS host reachable from the management network:
# $ProductKey = "D764K-2NDRG-47T6Q-P8T8W-YP6DF"   # WS2025 Datacenter KMS client key (GVLK)

New-Item -ItemType Directory -Path $BaseDir -Force | Out-Null

# Mount the ISO and pick the edition
$isoDrive = (Mount-DiskImage -ImagePath $Iso -PassThru | Get-Volume).DriveLetter
$wim = "$($isoDrive):\sources\install.wim"
Get-WindowsImage -ImagePath $wim | Format-Table ImageIndex, ImageName
$index = (Get-WindowsImage -ImagePath $wim | Where-Object ImageName -like $Edition).ImageIndex
"Using index $index"

# Create and partition the VHDX (UEFI / Gen2 layout)
New-VHD -Path $BaseVhdx -SizeBytes 60GB -Dynamic | Out-Null
$diskNo = (Mount-VHD -Path $BaseVhdx -Passthru | Get-Disk).Number
@"
select disk $diskNo
convert gpt
create partition efi size=260
format quick fs=fat32 label="System"
assign letter=S
create partition msr size=16
create partition primary
format quick fs=ntfs label="Windows"
assign letter=W
"@ | Set-Content "$env:TEMP\dp.txt" -Encoding ascii
diskpart /s "$env:TEMP\dp.txt"

# Apply Windows and make it bootable
Expand-WindowsImage -ImagePath $wim -Index $index -ApplyPath "W:\"
bcdboot W:\Windows /s S: /f UEFI
```

> If `S:` or `W:` is already used on the host, change the two letters in the diskpart text and in the two commands above.

**AVMA** (Automatic Virtual Machine Activation) activates the guest through the activated Datacenter host, over the Hyper-V Data Exchange (KVP) integration service. No network or KMS is needed.
Requirements: the host is Datacenter and activated (1.1 §10), and the VM has the "Key-Value Pair Exchange" integration service enabled (`New-InfraVM` does this).

**Optional – offline servicing (recommended):** the image comes straight from the ISO, so every VM would start unpatched. Inject the latest Windows Server 2025 cumulative update into the mounted image now:

1. On a machine with internet, download the latest WS2025 **cumulative update (.msu)** from the Microsoft Update Catalog. Download every MSU it lists as a prerequisite too (checkpoint CUs).
2. Copy them into one folder on HV01, e.g. `C:\ISO\CU\`.

```powershell
# HV01 – while W:\ is still mounted
Add-WindowsPackage -Path "W:\" -PackagePath "C:\ISO\CU\"      # the folder: DISM applies the MSUs in the right order
Get-WindowsPackage -Path "W:\" | Where-Object ReleaseType -eq "Update" | Select-Object PackageName, InstallTime
```

## 3. `New-InfraVM` helper (save once, reuse everywhere)

```powershell
# HV01
New-Item -ItemType Directory -Path C:\Build -Force | Out-Null
@'
function New-InfraVM {
    param(
        [Parameter(Mandatory)] [string] $Name,
        [int]    $vCPU       = 2,
        [int64]  $RAM        = 8GB,
        [int64]  $OSDiskSize = 100GB,
        [Parameter(Mandatory)] [string] $Path,        # D:\VMs (local) or C:\ClusterStorage\CSV01 (cluster)
        [Parameter(Mandatory)] [string] $BaseVhdx,
        [string] $Switch     = "LS-Converged",
        [int]    $Vlan       = 100
    )
    $vhdDir = Join-Path $Path "$Name\Virtual Hard Disks"
    New-Item -ItemType Directory -Path $vhdDir -Force | Out-Null
    $osDisk = Join-Path $vhdDir "$Name-OS.vhdx"
    Copy-Item -Path $BaseVhdx -Destination $osDisk
    Resize-VHD -Path $osDisk -SizeBytes $OSDiskSize

    New-VM -Name $Name -Generation 2 -MemoryStartupBytes $RAM -VHDPath $osDisk -SwitchName $Switch -Path $Path | Out-Null
    Set-VM -Name $Name -ProcessorCount $vCPU -StaticMemory -AutomaticStartAction Start -AutomaticStopAction ShutDown -CheckpointType Production
    Set-VMFirmware -VMName $Name -EnableSecureBoot On -SecureBootTemplate MicrosoftWindows
    Set-VMNetworkAdapterVlan -VMName $Name -Access -VlanId $Vlan
    Enable-VMIntegrationService -VMName $Name -Name "Guest Service Interface"    # Copy-VMFile
    Enable-VMIntegrationService -VMName $Name -Name "Key-Value Pair Exchange"    # required for AVMA activation
    Get-VM -Name $Name
}

function Wait-VMReady {
    param([Parameter(Mandatory)][string]$Name, [Parameter(Mandatory)][pscredential]$Credential)
    do { Start-Sleep -Seconds 15
         $ok = Invoke-Command -VMName $Name -Credential $Credential -ScriptBlock { $true } -ErrorAction SilentlyContinue
    } until ($ok)
    "$Name is ready"
}

function Expand-GuestC {
    param([Parameter(Mandatory)][string]$Name, [Parameter(Mandatory)][pscredential]$Credential)
    Invoke-Command -VMName $Name -Credential $Credential -ScriptBlock {
        $max = (Get-PartitionSupportedSize -DriveLetter C).SizeMax
        Resize-Partition -DriveLetter C -Size $max -ErrorAction SilentlyContinue
        Get-Volume -DriveLetter C | Select-Object DriveLetter, @{n='SizeGB';e={[math]::Round($_.Size/1GB)}}
    }
}

# Windows Update inside a VM until nothing is left. No extra modules: the Windows Update Agent API runs as
# SYSTEM through a one-time scheduled task (the WU API refuses download/install from a remote session).
# Works the same against Microsoft Update (direct or through the WinHTTP proxy) and against WSUS (GPO, 2.1 §7).
# Stops with an error (never loops forever) if WU fails or no result arrives within -TimeoutMinutes.
function Update-GuestWindows {
    param([Parameter(Mandatory)][string]$Name, [Parameter(Mandatory)][pscredential]$Credential, [int]$TimeoutMinutes = 90)
    $wu = {
        $out = "C:\Windows\Temp\wu-result.txt"
        try {
            $s = New-Object -ComObject Microsoft.Update.Session
            $found = $s.CreateUpdateSearcher().Search("IsInstalled=0 and IsHidden=0 and Type='Software'").Updates
            if ($found.Count -eq 0) { "0|False" | Set-Content $out; return }
            $coll = New-Object -ComObject Microsoft.Update.UpdateColl
            foreach ($u in $found) { if (-not $u.EulaAccepted) { $u.AcceptEula() }; [void]$coll.Add($u) }
            $d = $s.CreateUpdateDownloader(); $d.Updates = $coll; [void]$d.Download()
            $i = $s.CreateUpdateInstaller();  $i.Updates = $coll; $r = $i.Install()
            "$($coll.Count)|$($r.RebootRequired)" | Set-Content $out
        } catch {
            "ERR|$($_.Exception.Message)" | Set-Content $out
        }
    }
    $removeTask = { Unregister-ScheduledTask -TaskName "WU-Now" -Confirm:$false -ErrorAction SilentlyContinue }
    do {
        Invoke-Command -VMName $Name -Credential $Credential -ArgumentList $wu.ToString() -ScriptBlock {
            param($code)
            Set-Content -Path C:\Windows\Temp\wu.ps1 -Value $code
            Remove-Item C:\Windows\Temp\wu-result.txt -ErrorAction SilentlyContinue
            $a = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-NoProfile -ExecutionPolicy Bypass -File C:\Windows\Temp\wu.ps1"
            Register-ScheduledTask -TaskName "WU-Now" -Action $a -User "SYSTEM" -RunLevel Highest -Force | Out-Null
            Start-ScheduledTask -TaskName "WU-Now"
        }
        $deadline = (Get-Date).AddMinutes($TimeoutMinutes)
        do { Start-Sleep -Seconds 60
             $res = "$(Invoke-Command -VMName $Name -Credential $Credential -ScriptBlock { Get-Content C:\Windows\Temp\wu-result.txt -ErrorAction SilentlyContinue })".Trim()
             if (-not $res -and (Get-Date) -gt $deadline) {
                 Invoke-Command -VMName $Name -Credential $Credential -ScriptBlock $removeTask
                 throw "$Name : no Windows Update result after $TimeoutMinutes min. Inside the VM check C:\Windows\Temp\wu-result.txt, Get-ScheduledTaskInfo WU-Now, Get-WindowsUpdateLog."
             }
        } until ($res)
        if ($res -like "ERR|*") {
            Invoke-Command -VMName $Name -Credential $Credential -ScriptBlock $removeTask
            throw "$Name : Windows Update failed: $($res.Substring(4)). Check the update source (0.2 §1 #17): netsh winhttp show proxy / WSUS GPO, then Get-WindowsUpdateLog inside the VM."
        }
        $count, $reboot = $res -split '\|'
        "$Name : installed $count update(s), reboot required = $reboot"
        if ($reboot -eq 'True') {
            Restart-VM -Name $Name -Type Reboot -Force -Wait -For Heartbeat
            Wait-VMReady -Name $Name -Credential $Credential | Out-Null
        }
    } while ([int]$count -gt 0)
    Invoke-Command -VMName $Name -Credential $Credential -ScriptBlock $removeTask
}

# Edition + activation status + OS build of a VM (for the Gates: Datacenter, Licensed, same build as the hosts)
function Test-GuestBaseline {
    param([Parameter(Mandatory)][string]$Name, [Parameter(Mandatory)][pscredential]$Credential)
    $hostBuild = Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion"
    Invoke-Command -VMName $Name -Credential $Credential -ScriptBlock {
        $v = Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion"
        $lic = (cscript //nologo C:\Windows\System32\slmgr.vbs /dli) -match "License Status"
        [pscustomobject]@{ VM = $env:COMPUTERNAME; Edition = $v.EditionID; Build = "$($v.CurrentBuild).$($v.UBR)"; License = "$lic".Trim() }
    } | Select-Object VM, Edition, Build, License, @{n='HostBuild';e={"$($hostBuild.CurrentBuild).$($hostBuild.UBR)"}}
}
'@ | Set-Content C:\Build\New-InfraVM.ps1

. C:\Build\New-InfraVM.ps1      # load it (run this line in every new PowerShell window)
```

Copy the helper and the base image to HV02 (DC02 is built there in 4.1). This needs the domain, so do it at the start of 4.1:

> **Update source** (0.2 §1 #17): Windows Update and activation run as **SYSTEM**, so a proxy must be the **WinHTTP** proxy (not a browser/user proxy). Before the domain exists, set it inside each VM (`netsh winhttp set proxy`, shown in 2.1). After 2.1, a GPO on `OU=Infrastructure` provides the proxy or WSUS for every server (2.1 §7). `Update-GuestWindows` works the same against WSUS.
>
> Expected `Update-GuestWindows` output (it loops until 0):
> ```
> DC01 : installed 5 update(s), reboot required = True
> DC01 : installed 1 update(s), reboot required = False
> DC01 : installed 0 update(s), reboot required = False
> ```
> If it fails, it stops with `… Windows Update failed: <message>` (or a timeout after 90 min). Check, inside the VM: `netsh winhttp show proxy` (or the WSUS GPO with `gpresult /r`), `C:\Windows\Temp\wu-result.txt`, and `Get-WindowsUpdateLog` (writes `WindowsUpdate.log` to the Desktop).
>
> `Test-GuestBaseline` is used in every VM Gate: `Edition` must be **ServerDatacenter**, `License` must be **Licensed**, and `Build` must equal `HostBuild`.

## 4. Copy / Paste into VMs (what makes it work)

| Layer | Setting | Where it's done |
|---|---|---|
| Host | `Set-VMHost -EnableEnhancedSessionMode $true` | 1.1 §8 (all hosts) |
| VM | Guest Service Interface enabled (for `Copy-VMFile`) | `New-InfraVM` |
| Guest | Desktop Experience edition + "Remote Desktop Services" service running (default) | Base image |
| Client | Hyper-V Manager on **MGMT01** → connect to the VM → **View → Enhanced Session**. In the connect dialog: **Show Options → Local Resources → Clipboard** ✔ | 5.3 |
| VMM | VMM console → right-click VM → **Connect or View → Connect via Console**. Enhanced session (clipboard) works when the host policy above is on | 6.x |
| Everyday | Plain **RDP** (`mstsc /v:SQL01`) supports clipboard and drive redirection | – |

Copy a **file** from the host into a VM (no network needed):

```powershell
# HV0x (the host running the VM)
Copy-VMFile -Name "DC01" -SourcePath "C:\ISO\tool.zip" -DestinationPath "C:\Temp\tool.zip" -FileSource Host -CreateFullPath
```

> Until MGMT01 exists (5.3) there's no GUI anywhere: Server Core hosts can't open a VM console.
> That's expected. Steps 2.1 → 5.2 are done with PowerShell Direct, which needs no clipboard.

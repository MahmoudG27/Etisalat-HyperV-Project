# 4.2 AD groups and service accounts (for Cluster, VMM, SQL, SDN)

> Replaces the `svc-vmm` part of `6. SCVMM.md`. Run on **DC01** (PowerShell Direct from HV01, or RDP once MGMT01 exists).
> Rule: **no service account in Domain Admins.** Each account gets only the local admin rights it needs.

## 1. What gets created

| Object | Type | Used for | Rights |
|---|---|---|---|
| `svc-vmm` | User | VMM service account (setup page "Service account") | Local admin on **VMM01** only |
| `svc-vmm-ras` | User | VMM **Run As** account to manage hosts/cluster | Member of `GG-HyperV-HostAdmins` |
| `svc-sdn` | User | NC `MgmtDomainAccount` + VMM network service credential | Member of `DL-NC-Admins` and `DL-NC-Users` |
| `svc-ncbackup` | User | **NC backup to `<BACKUP-SHARE>\NC`**: the share credential stored inside the Network Controller (8.4 §7). Vault entry **`NC-Backup`**. **No interactive logon** | Modify on `<BACKUP-SHARE>\NC` (share + NTFS) only |
| `GG-HyperV-HostAdmins` | Global group | Local Administrators on HV01–HV04 | – |
| `GG-VMM-Admins` | Global group | VMM "Administrator" role + local admin on VMM01 | Put your admin users here |
| `GG-SQL-Admins` | Global group | `sysadmin` on SQL01 | Put your admin users here |
| `DL-NC-Admins` | **Domain Local** group | NC management security group (Microsoft requires Domain Local) | – |
| `DL-NC-Users` | **Domain Local** group | NC clients security group (REST access) | – |

## 2. Create them

```powershell
Import-Module ActiveDirectory
$root   = (Get-ADDomain).DistinguishedName
$svcOU  = "OU=Service Accounts,OU=Infrastructure,$root"
$grpOU  = "OU=Groups,OU=Infrastructure,$root"
$domain = (Get-ADDomain).DNSRoot

# Groups
New-ADGroup -Name "GG-HyperV-HostAdmins" -GroupScope Global      -GroupCategory Security -Path $grpOU
New-ADGroup -Name "GG-VMM-Admins"        -GroupScope Global      -GroupCategory Security -Path $grpOU
New-ADGroup -Name "GG-SQL-Admins"        -GroupScope Global      -GroupCategory Security -Path $grpOU
New-ADGroup -Name "DL-NC-Admins"         -GroupScope DomainLocal -GroupCategory Security -Path $grpOU
New-ADGroup -Name "DL-NC-Users"          -GroupScope DomainLocal -GroupCategory Security -Path $grpOU

# Service accounts: each gets its OWN long random password (store them in the password vault)
foreach ($u in @(
    @{n="svc-vmm";     d="VMM service account"},
    @{n="svc-vmm-ras"; d="VMM Run As - Hyper-V hosts management"},
    @{n="svc-sdn";     d="SDN Network Controller management + VMM network service"})) {
    $pw = Read-Host "Password for $($u.n)" -AsSecureString
    New-ADUser -Name $u.n -SamAccountName $u.n -UserPrincipalName "$($u.n)@$domain" -Description $u.d `
        -Path $svcOU -AccountPassword $pw -Enabled $true -PasswordNeverExpires $true -CannotChangePassword $true
}

# Memberships
Add-ADGroupMember -Identity "GG-HyperV-HostAdmins" -Members "svc-vmm-ras"
Add-ADGroupMember -Identity "DL-NC-Admins"         -Members "svc-sdn"
Add-ADGroupMember -Identity "DL-NC-Users"          -Members "svc-sdn"
Add-ADGroupMember -Identity "GG-VMM-Admins"        -Members "Administrator"     # + your named admin accounts
Add-ADGroupMember -Identity "GG-SQL-Admins"        -Members "Administrator"     # + your named admin accounts
Add-ADGroupMember -Identity "DL-NC-Users"          -Members "svc-vmm"           # runs the NC + VMM DB backup task on VMM01 (8.4 §7)
```

NC backup account (used from the SDN phase, 8.4 §7). Create it now with the others:

```powershell
# DC01
$pw = Read-Host "Password for svc-ncbackup (store in vault: NC-Backup)" -AsSecureString
New-ADUser -Name "svc-ncbackup" -SamAccountName "svc-ncbackup" -UserPrincipalName "svc-ncbackup@$domain" `
    -Description "NC backup to <BACKUP-SHARE>\NC - no interactive logon" `
    -Path $svcOU -AccountPassword $pw -Enabled $true -PasswordNeverExpires $true -CannotChangePassword $true
```

- **No interactive logon:** add `svc-ncbackup` to the *Deny log on locally* and *Deny log on through Remote Desktop Services* user rights (GPO on `OU=Infrastructure` and `OU=Domain Controllers`). It's only used for SMB access to the share.
- **Share + NTFS** (on the backup server, owner: Etisalat backup team): `svc-ncbackup` = **Change** on the share and **Modify** on the `NC` folder. Nothing else.

> **Machine account quota:** `svc-sdn` joins NC01–NC03 (and later MUX/GW VMs) to the domain. A normal user can join up to 10 computers by default (`ms-DS-MachineAccountQuota = 10`), which is enough. If your security team set the quota to 0, delegate "Create/Delete Computer objects" on `OU=SDN` to `svc-sdn`.

> **gMSA option:** VMM 2025 supports a gMSA as its service account. If your security policy needs it, create the KDS root key now, because it needs 10 hours before first use, and use `ETISALAT\gmsa-vmm$` in 6.2 instead of `svc-vmm`.

## 3. Make `GG-HyperV-HostAdmins` local admin on all hosts

```powershell
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock {
    Add-LocalGroupMember -Group "Administrators" -Member "ETISALAT\GG-HyperV-HostAdmins"
    Get-LocalGroupMember -Group "Administrators"
}
```

(For the 12 old servers later: use a GPO "Restricted Groups / Local Users and Groups" on `OU=Hyper-V Hosts`, so new hosts get it automatically.)

# 6.5 Deploy the SDN Network Controller (3 nodes) from VMM

> Source: Microsoft "Set up an SDN network controller in the VMM fabric" (VMM 2025), adapted to this environment.
> Result: NC01–NC03 running as HA VMs on CSV01, REST endpoint `https://ncrest.etisalat.local` (10.10.100.50), added to VMM as a **Network Service** managing host group **SDN**.

## 0. Pre-flight checklist

- [ ] 6.4 Gate passed (logical switch on all hosts, no extensions, compliant).
- [ ] Hosts are **Datacenter** edition and fully patched (same build).
- [ ] AD: `DL-NC-Admins`, `DL-NC-Users` (Domain Local) contain `svc-sdn` (4.2).
- [ ] Run As: `RA-SDN`, `RA-NC-LocalAdmin` exist (6.3).
- [ ] IP pool `IPP-Management` has ≥ 3 free IPs and **10.10.100.50 reserved**.
- [ ] VLAN 200 (HNV-PA) is trunked to NIC1/NIC2 on all hosts and routed by the network team (needed in 6.6).

## 1. Prepare the NC virtual hard disk (generalized WS2025 Datacenter)

On **HV01**, build a Datacenter base the same way as 1.2. Re-run the 1.2 §2 block with these values:

```powershell
$Edition    = "*Datacenter (Desktop Experience)*"
$BaseVhdx   = "C:\ClusterStorage\CSV01\_Base\WS2025-DC-DE.vhdx"
$ProductKey = "D764K-2NDRG-47T6Q-P8T8W-YP6DF"     # WS2025 Datacenter GVLK (or your MAK/AVMA)
```

Then patch it and generalize it:

```powershell
. C:\ClusterStorage\CSV01\_Base\Build\New-InfraVM.ps1
New-InfraVM -Name NC-IMG -vCPU 2 -RAM 4GB -OSDiskSize 60GB -Path "C:\ClusterStorage\CSV01\_Build" -BaseVhdx "C:\ClusterStorage\CSV01\_Base\WS2025-DC-DE.vhdx" -Vlan 100
Start-VM NC-IMG
$local = Get-Credential "Administrator"
Wait-VMReady -Name NC-IMG -Credential $local
```

Inside NC-IMG (Hyper-V Manager console from MGMT01, or PowerShell Direct):
1. Give it a temporary IP (for example `10.10.100.49`) so it can reach Windows Update/WSUS. **Do not join the domain.**
2. `sconfig` → 6 → install **all** updates → reboot → repeat until nothing is left (the NC VMs must match the hosts' patch level).
3. Remove the temporary IP, delete the old answer file, generalize:

```powershell
Remove-Item C:\Windows\Panther\unattend.xml -Force -ErrorAction SilentlyContinue
Get-NetIPAddress -IPAddress 10.10.100.49 | Remove-NetIPAddress -Confirm:$false
C:\Windows\System32\Sysprep\sysprep.exe /generalize /oobe /shutdown /mode:vm
```

When it's off, copy the disk into the library and delete the VM:

```powershell
Copy-Item "C:\ClusterStorage\CSV01\_Build\NC-IMG\Virtual Hard Disks\NC-IMG-OS.vhdx" "\\VMM01\MSSCVMMLibrary\VHDs\WS2025-DC-NC.vhdx"
Remove-VM NC-IMG -Force
Remove-Item "C:\ClusterStorage\CSV01\_Build\NC-IMG" -Recurse -Force
```

VMM console → **Library** → refresh → `VHDs\WS2025-DC-NC.vhdx` → **Properties** → Operating system **Windows Server 2025 Datacenter**.

## 2. Download the NC service templates

On MGMT01 (internet):

```powershell
Invoke-WebRequest "https://github.com/microsoft/SDN/archive/refs/heads/master.zip" -OutFile C:\Install\SDN.zip
Expand-Archive C:\Install\SDN.zip -DestinationPath C:\Install\SDN -Force
Copy-Item "C:\Install\SDN\SDN-master\VMM\Templates\NC" "\\VMM01\MSSCVMMLibrary\SDN\NC" -Recurse -Force
Get-ChildItem "\\VMM01\MSSCVMMLibrary\SDN\NC"
```

You should see `Network Controller Production Generation 2 VM.xml` and the folders `NcSetup.cr`, `ServerCertificate.cr`, `NcCertificate.cr`, `TrustedRootCertificate.cr`, `EdgeDeployment.cr`.

## 3. REST name in DNS + SSL certificate

**DNS** (on DC01). REST uses a **static IP** here (nodes are in the same subnet), so the A record is created manually:

```powershell
Add-DnsServerResourceRecordA -ZoneName "etisalat.local" -Name "ncrest" -IPv4Address 10.10.100.50 -CreatePtr
Resolve-DnsName ncrest.etisalat.local
```

**Certificate** (on **VMM01**, as Microsoft requires). Self-signed, valid for 5 years. Put a reminder in the calendar: renewing an NC certificate is a planned change.

```powershell
$cert = New-SelfSignedCertificate -KeyUsageProperty All -Provider "Microsoft Strong Cryptographic Provider" `
        -FriendlyName "NC-REST" -DnsName @("ncrest.etisalat.local") `
        -CertStoreLocation Cert:\LocalMachine\My -NotAfter (Get-Date).AddYears(5)

$pfxPwd = Read-Host "PFX password (needed again as ServerCertificatePassword)" -AsSecureString
$nc = "L:\MSSCVMMLibrary\SDN\NC"
Export-PfxCertificate -Cert $cert -FilePath "$nc\ServerCertificate.cr\ncrest.pfx" -Password $pfxPwd
Export-Certificate    -Cert $cert -FilePath "$nc\NcCertificate.cr\ncrest.cer"

# Trust it on VMM01
Import-Certificate -FilePath "$nc\NcCertificate.cr\ncrest.cer" -CertStoreLocation Cert:\LocalMachine\Root
```

On **MGMT01**, trust it too (needed for the validation commands in step 9):

```powershell
Import-Certificate -FilePath "\\VMM01\MSSCVMMLibrary\SDN\NC\NcCertificate.cr\ncrest.cer" -CertStoreLocation Cert:\LocalMachine\Root
```

Rules (from Microsoft):
- `ServerCertificate.cr` must contain **exactly one** `.pfx`.
- `NcCertificate.cr` gets the `.cer`.
- `TrustedRootCertificate.cr` stays **empty** for a self-signed certificate, but must still exist and be mapped.
- With an enterprise CA instead: subject = `ncrest.etisalat.local`, EKU Server Authentication (1.3.6.1.5.5.7.3.1), and the CA's `.cer` goes in `TrustedRootCertificate.cr`.

Refresh the library: `Get-SCLibraryShare | Read-SCLibraryShare`.

## 4. Import the service template

VMM → **Library → Import Template** → `\\VMM01\MSSCVMMLibrary\SDN\NC\Network Controller Production Generation 2 VM.xml`

| Resource in template | Map to |
|---|---|
| `WinServer.vhdx` | `WS2025-DC-NC.vhdx` |
| `NCSetup.cr` | `SDN\NC\NcSetup.cr` |
| `ServerCertificate.cr` | `SDN\NC\ServerCertificate.cr` |
| `TrustedRootCertificate.cr` | `SDN\NC\TrustedRootCertificate.cr` (empty) |

## 5. Customize the template (Designer)

Library → Templates → Service Templates → the NC template → **Open Designer** → double-click the machine tier:

| Section | Setting |
|---|---|
| Hardware → Processor / Memory | 4 vCPU · 8 GB **static** (as in your sizing table) |
| Hardware → **Availability** | ✔ **Make this virtual machine highly available** + availability set (e.g. `AS-NC`), so the 3 NCs never share one host |
| OS Configuration → Identity | Computer name `NC##` (gives NC01, NC02, NC03) |
| OS Configuration → Product key | Your Datacenter key (or the GVLK) |
| Network adapter | Connected to `Management` VM network · IPv4 **Static** from pool `IPP-Management` (default in template) |

**Save and Validate.**

## 6. Configure and deploy the service

Right-click the template → **Configure Deployment** → Name **`NC`** (this name is used in the connection string) → Destination **`SDN`** host group → Network `Management`.

| Setting | Value |
|---|---|
| ClientSecurityGroup | `ETISALAT\DL-NC-Users` |
| DiagnosticLogShare | *(optional)* `\\VMM01\MSSCVMMLibrary\SDN\NCLogs` |
| LocalAdmin | Run As `RA-NC-LocalAdmin` |
| Management | `Management` |
| MgmtDomainAccount | Run As `RA-SDN` |
| MgmtDomainAccountName | `ETISALAT\svc-sdn` |
| MgmtDomainAccountPassword | password of svc-sdn |
| MgmtDomainFQDN | `etisalat.local` |
| MgmtSecurityGroup | `ETISALAT\DL-NC-Admins` |
| **RestEndPoint** | **`10.10.100.50/24`** (REST IP in CIDR: the nodes are in the same subnet, so Microsoft requires an IP here) |
| ServerCertificatePassword | the PFX password from step 3 |

→ **Refresh Preview** (the VMs turn from red to placed on 3 different hosts) → **Deploy Service**.
Typical duration: 30–60 minutes. Follow **Jobs**.

If it fails: **VMs and Services → Services → NC → Delete**, fix the cause (see the job error + `C:\ProgramData\VMMLogs` and `C:\Windows\Tracing` on the NC VMs), then deploy again.

## 7. Allow the NC nodes to register their SPN (Windows Server 2019+ requirement)

Without this, VMM's Kerberos REST calls to NC fail. Run on **DC01** once NC01–NC03 exist in AD:

```powershell
$ncNodes = "NC01","NC02","NC03"
foreach ($target in $ncNodes) {
    $dn = (Get-ADComputer $target).DistinguishedName
    foreach ($node in $ncNodes) {
        dsacls $dn /G "ETISALAT\$($node)`$:WS;Validated write to service principal name"
        dsacls $dn /G "ETISALAT\$($node)`$:RPWP;servicePrincipalName"
    }
}
# Move them to the SDN OU (optional, tidy)
$ncNodes | ForEach-Object { Get-ADComputer $_ | Move-ADObject -TargetPath "OU=SDN,OU=Infrastructure,DC=etisalat,DC=local" }
```

Check after a few minutes (restart the NC VMs one by one if it doesn't appear):

```powershell
setspn -Q "HTTP/ncrest.etisalat.local"
```

## 8. Add NC to VMM as a Network Service

**Fabric → Networking → Network Service → Add Network Service**

| Page | Value |
|---|---|
| Name | `NC` |
| Manufacturer / Model | **Microsoft** / **Microsoft network controller** |
| Credentials | Run As **`RA-SDN`** (member of the NC clients group) |
| Connection string | `serverurl=https://ncrest.etisalat.local;servicename=NC` |
| Review certificates | Verify it's the `ncrest.etisalat.local` certificate → ✔ **These certificates have been reviewed and can be imported to the trusted certificate store** |
| Provider | **Scan Provider** → `isNetworkController = true` |
| Host group | ✔ **SDN** |

**Finish.** This job onboards the hosts:
- Installs the NC Host Agent and SLB Host Agent on HV01–HV04.
- Enables the **Azure VFP** switch extension on `LS-Converged` (the switch becomes an "SDN switch").
- Pushes the host certificates.

## 9. Validate NC

From **MGMT01**:

```powershell
# NC cluster health. REST calls need an account in DL-NC-Users (svc-sdn), or add your admin account to that group
$uri   = "https://ncrest.etisalat.local"
$ncCred = Get-Credential "ETISALAT\svc-sdn"
Get-NetworkControllerServer -ConnectionUri $uri -Credential $ncCred | ForEach-Object { "$($_.ResourceId)  $($_.Properties.Status)" }
Invoke-Command -ComputerName NC01 -ScriptBlock { Get-NetworkControllerNode | Format-Table Name, Status, Server }

# Hosts onboarded
Invoke-Command -ComputerName HV01,HV02,HV03,HV04 -ScriptBlock {
    Get-Service NcHostAgent, SlbHostAgent | Select-Object @{n='Host';e={$env:COMPUTERNAME}}, Name, Status
    Get-VMSwitchExtension -VMSwitchName "LS-Converged" | Where-Object Name -like "*VFP*" | Select-Object Name, Enabled
}
```

Expected:
- 4 servers in NC, all `Up`.
- 3 NC nodes `Up`.
- `NcHostAgent` / `SlbHostAgent` Running on every host.
- VFP extension `Enabled = True`.
- **Infrastructure VMs still reachable** (ping DC01, SQL01, VMM01 from MGMT01).

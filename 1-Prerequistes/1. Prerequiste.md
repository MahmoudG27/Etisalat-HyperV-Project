# Is only one GW enough for 25 clients?
-> Numerically enough, but this is not the right design for you.

1) Not all clients need GW. The GW only works in two cases:
# IPsec site-to-site: Same as the NSX Edge VPN they have now.
# L3 for FortiGate: VLAN + /29 for each client.

# NAT, public IP, and load balancing are all for SLB/MUX, not GW.
-> Limitations in Microsoft documentation:
# 50 VM network per gateway, and 25 clients within this limit.
# The throughput is the problem: IPsec only takes 3/20 of the capacity. This means that if the capacity is 10 Gbps, the entire IPsec is about 1.5 Gbps, divided among all clients.

# The 1+1 problem:
-> All clients on one VM are active.
# If it fall, all 25 agents failover at the same time (large blast radius).
# The second VM is an empty base.

# My suggestion: 2+1, meaning 3 GW VMs.
-> Two active, and the clients are divided into them (about a text on each one). One standby.
# The throughput remains weak, and if it falls active, only half of the clients will be affected.
# We have 4 hosts, so the 3 GWs are located on 3 different hosts.
# Microsoft requires N ≤ M, and 2+1 meets the condition.
